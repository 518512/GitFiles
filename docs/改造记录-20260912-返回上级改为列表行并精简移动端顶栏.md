# 改造记录 20260912 返回上级改为列表内 ".." 行并精简移动端顶栏

## 修改了什么

用户指出上一轮的两个判断失误，本轮更正。

### 1. 「返回上一级」位置与形态都错了 → 改为列表内的 ".." 行

**上一轮的错误**：做成了工具栏里一个独立的箭头按钮，放在面包屑左侧。

**问题**：

- **位置错**：文件管理器的常识是「进入子目录后，列表最上方有一个 `..` 项」，
  而不是顶栏多一个按钮。顶栏按钮与"当前目录内容"不在同一个视觉上下文里。
- **形态错**：单独的箭头图标无法表达"回到上一级"这一语义。

**本次修复**：

```text
列表视图                          网格视图
┌──────────────────────────────┐  ┌──────────────────┐
│ 📁↗  ..                      │  │   📁↗            │
├──────────────────────────────┤  │   ..             │
│ 📁  docs                      │  ├──────────────────┤
│ 📄  README.md                 │  │   📁  docs        │
└──────────────────────────────┘  └──────────────────┘
```

- 位置：**列表 / 网格的最上方**，作为第一个条目。
- 图标：**文件夹 + 右上角向上箭头角标**（`.go-up-icon-wrap`）。
  只有文件夹会和普通目录项混淆，叠加箭头后才能一眼识别为"返回上级"。
  图标颜色用 `--color-muted`，hover 变 `--color-accent`。
- 名称：`..`
- 两种视图各自复用现有结构（`.file-item` / `.list-row`），只保留名称列。
- 可访问性：`role="button"`、`tabIndex=0`、Enter/Space 均可触发、
  `title="返回上一级"`、`:focus-visible` 描边。
- **根目录不显示**：避免一个永远不可点的入口。

**连带修复**：空目录但可以返回上级时，不再显示「此文件夹为空」空态——
那会与列表里的 `..` 行自相矛盾（空态是独立容器，会把列表遮住）。

### 2. 移动端顶栏太挤 → 隐藏面包屑

用户指出移动端「仓库名 › 子目录」占用过多顶部空间。

**修复**：移动端（`max-width: 768px`）隐藏 `.ribbon .address-bar`。

依据：当前目录信息已有更合适的载体——

```text
当前目录是什么      列表里的 ".." 行 + 列表内容本身
所在的仓库          仓库头（.repository-header：仓库名 / 分支 / 公开私有）
如何跳转            列表内 ".." 行、侧栏目录树、品牌按钮回首页
```

移动端布局随之简化：

```text
第 1 行  导航 · 品牌 · [弹性] · 刷新 · ＋ · 头像
第 2 行  搜索 · 视图切换          （原第 2 行还有面包屑）
```

顺手把第 2 行的 `order` 从 5/6/7 顺延为 5/6，去掉空档。

> 说明：上一轮我曾把面包屑比作「浏览器的地址栏」而保留它，
> 但这个类比不成立——浏览器的地址栏可以直接编辑跳转，而这里的面包屑做不到。
> 真正的目录导航由 `..` 行与侧栏承担，因此移动端隐藏它是合理的。

## 遗留问题

- **未真机验证**：`..` 行的图标叠加效果、".." 在网格视图中的观感、
  移动端隐藏面包屑后的工具栏高度，需在浏览器 / Android 确认。
- `..` 行不参与多选与框选（它是空态导航项，不加入 `state.files`），
  这是有意设计；若将来需要键盘上下键在列表中移动焦点，需要额外处理。
- 本地存储的 `folderParentId` 依赖 `disk.entries` 或 `breadcrumbs` 推导，
  与上一轮相同，disk 结构变化时需同步调整。
- **fork 仍未解除**：需在 GitHub 网页操作（Settings → General → Danger Zone →
  Leave fork network）。文档已如实描述。
