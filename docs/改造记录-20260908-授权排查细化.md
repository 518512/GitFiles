# 改造记录：细化 GitHub 授权过期的排查步骤

- 日期：2026-09-08
- 关联：`docs/改造记录-20260908-部署排查小节.md`

## 背景

用户反馈：GitHub 侧 App 安装状态检查均正常（Cloudflare Workers App 已安装、Repository
access 包含 fork），但一键部署仍提示 "Your GitHub authorization has expired … reinstall
the Cloudflare GitHub App"。

## 原因分析

- "App 已安装" ≠ "授权会话有效"。该报错指向 **Cloudflare 记住的账号级 OAuth 连接**（部署
  向导的身份授权）过期，与 App 安装（installation）是两个独立状态；两边不同步即报此错。
- 报错附带的文档链接是 `/pages/configuration/git-integration/...`（Pages 路径），提示用户
  走的入口可能仍是旧「Pages → Connect to Git」流程，而非 Workers 化后的按钮 / Import a
  repository（Workers Builds）入口。

## 修改了什么

双语 README 排查表中 "GitHub authorization has expired" 条目细化为**完全重置**流程：

1. GitHub 卸载 `Cloudflare Workers` / `Cloudflare Pages` 两个 App
2. GitHub → Authorizations 撤销 `Cloudflare Dashboard` 授权
3. Cloudflare 侧 Disconnect GitHub 连接
4. 删除之前失败创建的旧项目
5. 无痕窗口重走部署向导，完成全新 App 安装

并强调 CLI 兜底路径（`npx wrangler login && npx wrangler deploy`）完全不经 Git 集成，
`CONFIG_*` 变量可在本地 export 后由 deploy 注入。

## 为什么改

用户实测表明"检查 App 安装"不足以解决该报错，需要给出状态级重置步骤；CLI 路径作为
不经 GitHub App 授权的保底方案需写明变量注入方法。
