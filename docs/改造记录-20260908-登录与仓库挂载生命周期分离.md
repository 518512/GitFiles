# 改造记录：登录（Authentication）与仓库挂载（Mutation）彻底分离

- 日期：2026-09-08
- 关联：`docs/代码审查-20260908-main系统审查与修复任务单.md` T2、
  `docs/改造记录-20260908-审查任务单T1至T5修复.md`

## 问题（用户裁决）

上轮 T2 的 `ensureGithubStorage()` 虽为二选一对话框，但 `signInWithGithub`
仍在"无盘"时**强制**调用它 —— 登录流程内依然绑定了 Mount 决策（只是从
"自动创建"变成"登录时必须选"），Authentication 与 Mutation 未真正分离。
原逻辑"首次登录自动创建 Drive-1"还造成隐式副作用：用户 GitHub 账号里
凭空多出仓库。

## 修改了什么

1. `js/app.js` `signInWithGithub()`：**纯认证** —— `acquireAccessToken()` →
   进入 explorer，绝不调用 createDisk / ensureGithubStorage / 任何
   POST /user/repos。
2. 欢迎空态：`index.html` / `404.html` 新增 `#no-storage-state`（Welcome back /
   No GitHub repository is mounted yet / [Add Repository]）；
   `renderCurrentView` 零挂载存储时显示欢迎态（替代空文件夹文案）；
   `#btn-add-repository` → `addRepositoryFromWelcome()` → 用户显式点击后才走
   `ensureGithubStorage()`（Connect existing ∥ Create new 二选一）。
3. `css/style.css`：`.empty-state .btn` 间距。

## 为什么改

产品语义应为"登录 GitHub 后管理我已有的 Repo"：登录只负责获取身份；
挂载/创建是用户显式发起的独立生命周期。消除隐式副作用（自动建仓）。

## 涉及文件

- `js/app.js`、`index.html`、`404.html`、`css/style.css`、`js/app-version.js`

- 端到端待部署验证：登录 → 直接进主界面欢迎空态 → Add Repository → 二选一
