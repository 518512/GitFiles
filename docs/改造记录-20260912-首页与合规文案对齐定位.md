用 GitHub API 实际查询（不是靠 git 本地状态判断）：

这两项**只能在 GitHub 网页上改**，无法通过 git 或代码修改。已在下方给出具体值。

### 2. 首页与首屏文案

原文案停留在「本地存储 + GitHub 仓库」的并列描述，与当前定位（以 GitHub Repository
为核心的 Git 文件工作区）不符。

```text
修改前  一个全屏、快速、安全的本地与 GitHub 仓库文件管理器。
修改后  把 GitHub Repository 当作云端文件系统：浏览、上传、编辑，并以正确的 Git 历史提交。
```

同步调整：

- `js/site-config.js` 的 `tagline`（用于生成页面描述）：
  「统一管理本地存储和 GitHub 仓库的文件管理器。」→
  「把 GitHub Repository 当作云端文件系统来浏览、编辑与提交的 PWA。」
- `js/app.js` 首页概览的三条空态/摘要文案，改为说明「GitHub Repository 就是你的云端文件系统」。
- `index.html` 新增**静态** `description` / `og:*` / `twitter:card` 标签。
  原因：`site-config.js` 是脚本注入，head 解析后才执行，**社交预览与搜索引擎抓取看不到**。

### 3. 顺带修掉一处合规问题：隐私政策写了不存在的 Google 支持

`privacy.html` 是**法律文本**，但仍在声明已经移除的 Google 集成——包括
「我们不会收到你的 Google 或 GitHub 密码」「Google Drive API」这类第三方服务清单。
这属于实质性的不准确。

已逐条更正：

| 原文 | 现状 |

「Google Drive 支持已移除」这一句是**有意保留**的，用来说明能力边界。

## 为什么改

- 定位文案是用户看到的第一个信息，停留在旧描述会让人误以为仍支持 Google Drive。
- 隐私政策描述不存在的第三方服务，在**开源项目**里尤其容易误导使用者的授权判断。
- fork 状态此前我只在文档里写了「已脱离」，但**没有核实过**，实际并未执行。这次用 API 确认。

## 遗留问题

### 必须由你在 GitHub 网页上完成的三项（我无法代做）

1. **解除 fork**：仓库 → **Settings → General → 拉到最底 Danger Zone → Leave fork network**
   （仓库 12MB < 1GB、公开、无子 fork，满足条件）。
   ⚠️ 不可逆，且会丢弃 issues / PR / wiki / stars / watchers（commit 历史保留）。
   据 API 显示当前 `has_issues: false`、`open_issues: 0`，应无数据损失。
2. **改仓库描述**（Settings → General → Description）：
   ```text
   把 GitHub Repository 当作云端文件系统的文件管理器（PWA），基于 Cloudflare Workers
   ```
3. **改 Homepage**（同页 Website 字段）：填你自己的 Worker 地址，不要保留上游 demo 链接。
