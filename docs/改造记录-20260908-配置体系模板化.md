# 改造记录：配置体系模板化，fork 用户零代码修改

- 日期：2026-09-08
- 关联：`docs/改造记录-20260908-品牌统一迁移.md`（遗留问题之一）

## 修改了什么

### 1. `js/config.js` 模板化（不再携带任何人的真实 ID）

- 移除上游作者的 `GITHUB_CLIENT_ID`（`Ov23liTZlYZHUnrINYnk`）与 Google `CLIENT_ID`，改为空占位
- 改为 `DEFAULT_CONFIG` + `window.CONFIG_OVERRIDES` 合并结构，顶部注释写明三种配置方式

### 2. 三层覆盖机制（优先级：构建注入 > 本地文件 > 模板默认）

| 层 | 文件 | 场景 |
|----|------|------|
| 模板默认 | `js/config.js`（入库） | 兜底 |
| 本地覆盖 | `js/config.local.js`（gitignored，模板 `js/config.local.example.js` 入库） | 本地 `serve.py` 开发 |
| 构建注入 | `js/config.runtime.js`（构建产物，gitignored） | Cloudflare Pages 部署 |

### 3. 新增 `scripts/build-config.mjs`

- Pages 构建期间读取环境变量 `CONFIG_GOOGLE_CLIENT_ID` / `CONFIG_GITHUB_CLIENT_ID` / `CONFIG_BASE_PATH`（/`CONFIG_GITHUB_SCOPES`），生成 `js/config.runtime.js`
- 变量名避开 GitHub Actions 保留的 `GITHUB_` 前缀，平台无关
- 幂等：无变量时生成空覆盖，构建永不因此失败

### 4. 接线

- `wrangler.jsonc` 增加 `"build": {"command": "node scripts/build-config.mjs"}`
- `index.html` / `notepad.html` / `404.html` 在 `config.js` 后加载 `config.local.js` + `config.runtime.js`（可选文件，缺失时静默跳过）
- `.gitignore` 增加 `js/config.runtime.js`
- `githubdisk.js` 的 `ensureConfigured()` 占位检测改为空值/`YOUR_*` 前缀，报错文案指向新配置途径
- 双语 README 新增「配置 Client ID（fork 用户无需改任何代码）」对照表

## 为什么改

用户指出：`js/config.js` 直接放 ID（且原为上游作者的 OAuth App）对其他 fork 用户不友好 —— 要么踩上游应用的 `redirect_uri` 错误，要么被迫修改 tracked 文件并与上游更新持续冲突。模板化 + 环境变量注入后，fork 用户在 Cloudflare 向导/控制台填变量即可完成部署配置。

## 涉及文件

- 修改：`js/config.js`、`js/githubdisk.js`、`wrangler.jsonc`、`index.html`、`notepad.html`、`404.html`、`.gitignore`、`README.md`、`README_EN.md`
- 新增：`js/config.local.example.js`、`scripts/build-config.mjs`

- `build-config.mjs` 双模式验证：无变量 → 空覆盖不失败；有变量 → 正确生成覆盖键
- 合并冒烟：`window.CONFIG_OVERRIDES` 正确覆盖 `GITHUB_CLIENT_ID`，其余默认值（`GITHUB_SCOPES`、`BASE_PATH`）保持
- 全部改动文件语法检查通过；引擎回归 32/32 通过
