# GitHub 仓库挂载与安全修复

## 修改了什么

- 将 GitHub 登录与仓库挂载解耦：登录只取得当前页面会话令牌，不创建或挂载仓库。
- “添加 GitHub 仓库”改为先列出当前授权账户可写的仓库，用户选择后才挂载；无可选项或列表请求失败时才允许手动输入 `owner/repository` 进行权限校验。
- 新建私有仓库保留为独立的显式操作，只有用户选择“Create new private repository”才会调用 GitHub 创建仓库 API。
- 挂载元数据仍可保存到 `localStorage`，但 GitHub token 不再序列化；历史持久化 token 在加载时被丢弃。刷新页面后需要重新授权，直到服务端 HttpOnly session 实现为止。
- Worker OAuth 交换接口限制为同源 POST，忽略客户端提交的 `client_secret`，仅使用 Worker 环境中的 `GITHUB_CLIENT_SECRET`。本地 `serve.py` 代理同步忽略客户端密钥。
- Git 操作引擎拒绝 `.`、`..`、空路径段和 NUL 字符的仓库路径。
- 空仓库首次提交改为仅创建一次分支 ref；并发创建 ref 统一映射为 `ConflictError`，不再创建后再次 PATCH 同一 ref。
- 对话框支持 `select` 字段，用于仓库选择。
- README 中英文同步为新的登录、挂载、令牌与测试语义。

## 为什么改

此前 GitHub 仓库生命周期中混合了认证、挂载和自动创建 `Drive-N` 仓库，导致登录后可能产生用户未确认的仓库；同时 token 被写入浏览器持久化存储，不符合项目的安全目标。Git 引擎的空仓库 ref 创建也存在重复更新与并发冲突分类不完整的问题。

## 测试情况

执行：

```bash
node --test tests/github-engine.test.mjs
node --check workers/entry.js
node --check js/githubdisk.js
node --check js/dialog.js
node scripts/build-config.mjs
git diff --check
```

结果：Git 引擎测试 `35 passed, 0 failed`；语法检查、构建和 diff 检查通过。

新增覆盖：不安全路径、空仓库单次 ref 创建、并发初始 ref 创建冲突。

## 遗留问题

- 目前只有客户端内存态 token；刷新后需要重新 OAuth/PAT 授权。GitHub App、Worker 服务端会话、D1 和 HttpOnly Cookie 尚未实现。
- 跨 GitHub 仓库移动需要目标仓库提交后再删除源仓库，Git 无法跨仓库提供单一原子提交；需要补偿/恢复工作流。
- Conflict Center 仍未提供内容级三方合并、差异查看与逐文件解决界面。
