# 改造记录：整体清理工作区冗余控件

## 修改了什么

- 统一为一条顶部工作区工具栏，保留导航开关、GitFiles、添加存储、当前仓库状态、刷新、路径、目录搜索、排序和视图切换。
- 删除重复或无业务价值的全局搜索、移动端三点区域菜单、概览页添加存储、概览页“查看仓库”、历史页单独刷新、侧栏根目录主页和侧栏重复添加存储入口。
- 顶部刷新根据当前视图刷新文件或提交历史，避免同功能的多个刷新按钮。
- “仓库”导航不再任意打开第一个仓库，改为展示所有已挂载 GitHub 仓库的独立仓库列表；“概览”展示全部已挂载存储。
- 删除侧栏树根节点的折叠状态和相关死代码，侧栏只展示实际存储树。
- 三横线按钮固定于 GitFiles 左侧：移动端打开 Drawer，桌面端收起或展开侧栏。
- 同步替换 `404.html` 的旧 Explorer DOM，保证回退入口与主入口使用同一套 UI，避免再次出现旧导航控件。
- 移除无调用的区域菜单和导航恢复函数，以及对应的无用样式。

## 为什么改

此前 UI V2 在旧文件管理器结构上叠加了新控件，造成同一行为有多个入口、概览和仓库语义不清、主入口与 404 回退入口不一致，并保留多项无法使用或不表达状态的控件。本次按唯一入口、唯一状态显示和实际 Repository Workspace 工作流统一处理。

## 涉及文件

`index.html`、`404.html`、`js/app.js`、`css/ui-v2.css`、`js/app-version.js`。

## 测试情况

- JavaScript 语法检查。
- Git 引擎和 Worker API 回归测试。
- 静态构建、主入口/404 UI 同步检查、无效控件残留检查。
- `git diff --check`。

## 遗留问题

- Repository Picker 仍使用当前已有的添加仓库 Dialog，未引入额外管理页面。
- 历史页展示最近 30 条提交，不含分页与提交详情。
- 旧 `style.css` 中仍有历史文件管理器样式，但当前主 UI 已由 `ui-v2.css` 覆盖；后续可在视觉回归稳定后单独逐段清除。
