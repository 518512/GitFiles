# 改造记录 20260912 修复 PWA 每次重开都要求重新登录

## 问题

用户真机反馈：**PWA 每次重新打开都要重新认证登录**。

## 排查过程（含一次误判）

第一轮我判断为「/api/* 响应缺 Cache-Control」，加了 `no-store`——
**这个修复有价值但不是根因**。本轮重新读代码，在一份旧记录里找到决定性证据：

`改造记录-20260908-GitHubApp过期token与重复授权.md` 明确记载：
**用户的 Client ID 是 GitHub App（Ov23 前缀），user access token 默认 8 小时过期**。

而 `workers/entry.js` 的会话寿命计算：

```js
const expiresAt = Date.now() + Number(tokenPayload.expires_in || 60*60*24*7) * 1000;
```

GitHub App 的交换响应里 `expires_in` ≈ 28800（8 小时），同时返回一个
**约 6 个月有效的 refresh_token** —— 被代码完全忽略了。

于是：

```text
登录 → D1 session 8 小时后过期（Cookie 虽是 7 天，但 /api/me 校验的是 D1 行）
     ↓
purgeExpiredSessions 把过期 session 与 ACL 一并删除
     ↓
隔夜重开 PWA → /api/me 401 → 登录页 → 重新走一遍 OAuth
```

「每次重新打开都要重新认证」与「隔夜重开」完全吻合。8 小时是一个
"当天看不出来、隔天必然复现"的周期，这也是它拖到现在才暴露的原因。

> 复盘：上一轮我修了缓存就收手，没有追问"为什么 /api/me 会 401"。
> 而答案其实躺在一周前的改造记录里。排查应先翻历史，再假设新问题。

## 修复：refresh_token 静默续期

### 1. 登录时把续期凭据落库

`sessions` 新增可选列：`refresh_token` / `refresh_expires_at` / `client_id`
（续期时 GitHub 要求 client_id，落库避免为此新增运行时配置）。

### 2. `requireSession` 过期时静默续期

```text
session 过期且有未过期的 refresh_token
  → POST github.com/login/oauth/access_token (grant_type=refresh_token)
  → 新 access_token / expires_at / 轮换后的 refresh_token 写回 D1
  → 请求继续，用户无感
无 refresh_token 或续期失败 → 如实 401
```

每个 API 路由都经过 `requireSession`，所以续期覆盖所有请求路径。

### 3. Cookie 寿命对齐

登录 Cookie 由固定 7 天改为「有 refresh 有效期则最长 180 天」。
否则 Cookie 先过期，会把已续期的会话重新打回登录页。

### 4. 列内省重构（连带修正）

新增三个可选列后，原来逐属性的 try/catch 级联难以为继，改为
**`PRAGMA table_info` 内省真实列名 + 动态拼语句**（每 isolate 一次）。
这顺带消除了上次"SELECT 有回退、INSERT 没有"这类不对称缺陷的土壤。

同时修正内省失败时的兜底：从「假设全部列存在」改为**最保守的旧列集合**
——保证核心登录路径可用，新列缺失只是功能降级。

### 5. 已知取舍

- GitHub 会**轮换** refresh_token（每次续期返回新值）。新值必须立即落库；
  并发请求同时续期存在极小的竞态窗口（旧 token 已被用掉），
  表现为偶发一次 401，重新登录即可。个人使用场景可接受，已记录。
- 未实现 installation token 与主动吊销（仍属 P-02）。

## 你需要做的一件事

**重新部署后，重新登录一次。** 这是最后一次手动登录——

- 新登录会写入 refresh_token，此后 8 小时的 token 过期会被自动续期
- 登录时执行这两条可选的 ALTER 可以补齐旧库列（不执行也能用，只是
  续期凭据存不进旧库，隔夜重开仍会要求登录）：

```sql
ALTER TABLE sessions ADD COLUMN refresh_token TEXT;
ALTER TABLE sessions ADD COLUMN refresh_expires_at INTEGER;
ALTER TABLE sessions ADD COLUMN client_id TEXT;
```

> 必须重新登录一次的原因：旧 session 行里没有 refresh_token，
> 修复无法为它续期。
