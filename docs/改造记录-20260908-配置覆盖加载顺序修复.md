# 改造记录：修复配置覆盖合并时机错误（构建注入从未生效）

- 日期：2026-09-08
- 关联：`docs/改造记录-20260908-配置体系模板化.md`

## 问题现象

用户在 Cloudflare 配置 `CONFIG_GITHUB_CLIENT_ID` 构建变量后（curl 验证
`/js/config.runtime.js` 注入内容正确），首页 GitHub 登录依旧报
"GitHub sign-in is not configured" —— 配置注入从未真正生效。

## 根因（本次改造引入的缺陷）

入口页脚本加载顺序错误：

```text
config.js（执行合并：读 window.CONFIG_OVERRIDES —— 此时尚不存在）
→ config.local.js（定义 CONFIG_OVERRIDES）
→ config.runtime.js（赋值 CONFIG_OVERRIDES）
```

`config.js` 的展开合并发生在覆盖文件定义之前，`CONFIG` 定格为默认值。
此前冒烟测试先设置 overrides 再加载 config.js，与浏览器真实顺序相反，
测试无效未捕获此缺陷。

## 修改了什么

- `index.html` / `notepad.html` / `404.html`：加载顺序调整为
  `config.local.js → config.runtime.js → config.js`（覆盖先定义、后合并；
  runtime 在 local 之后，同名键构建注入优先）
- `js/app-version.js` 版本戳更新

## 为什么改

部署环境变量注入是「fork 用户零代码修改配置」的核心机制，当前完全失效。

## 涉及文件

- `index.html`、`notepad.html`、`404.html`、`js/app-version.js`

## 测试情况

- 冒烟（按浏览器真实顺序全模拟）：`runtime-value` 覆盖 `local-value` ✓、
  local 额外键保留 ✓、默认值（GITHUB_SCOPES）不受影响 ✓
- 引擎回归 32/32 通过
