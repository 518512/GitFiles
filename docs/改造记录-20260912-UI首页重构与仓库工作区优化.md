# 改造记录 20260912 UI 首页重构与仓库工作区优化

## 修改了什么

按确认的方案实施 UI 优化 P0–P4。

### P0 首页重构为真正的入口

首页此前只渲染「已挂载」的 storage，零状态只有一句「尚未挂载存储」，内容区没有任何
主行动按钮；而 `no-storage-state` 那个带按钮的欢迎空态只在 `level !== 'home'` 时才
显示，首页根本走不到。

现在首页结构为：

```text
概览                                        [添加存储]
──────────────────────────────────────────────────
最近访问
  ▸ owner/repo   GitHub · 私有 · 分支 main · docs/    3 分钟前

已挂载存储          2 个仓库 · 1 个本地存储 · 3 个已挂载
  ▸ owner/repo   GitHub · 私有 · 分支 main
  ▸ 本地存储
```

- 新增**最近访问**：`localStorage` 记录 `disk id + 时间 + 最后停留目录`
  （`storage_hub_recent_disks`，上限 6 条），进入任意 storage 时更新。
- 统计从三个大卡片降级为标题旁一行小字（其中「已挂载存储」原本恒等于前两者之和）。
- 按用户确认：**不显示**未挂载的「可添加仓库」，首页只展示已挂载项。
- 首页不发起任何额外 API 请求（不为了显示每个仓库的提交时间而逐个读 tree）。

### P1 零状态给出出口

- 首页标题行右侧新增 `#btn-overview-add`（复用顶栏「＋」的添加存储菜单），
  零状态文案也改为明确指引「点击右上角添加存储」。
- 合并三套重复空态：删除静态 `#no-storage-state` 与其重复文案，
  `#overview-empty`、`#overview-summary` 统一由 `renderOverview()` 渲染。

### P2 合并侧栏重复语义

原侧栏「概览」和「仓库」两个导航项其实渲染同一个 `overview-panel`，只切
`overviewMode`；而进入仓库后面包屑又会出现「仓库」层级，语义重复。
现在侧栏只保留单一「概览」，`state.overviewMode` 整体移除。

### P3 仓库工作区

- **空目录空态带动作**：原来只有一句「此文件夹为空」。现在由 `renderEmptyState()`
  统一渲染图标 / 标题 / 提示 / 动作，提供「上传文件」与「新建文件」；
  搜索无结果、回收站为空、README/历史视图各有对应文案，不再出现「此文件夹为空」
  这种错误提示。
- **新增 README 视图**：仓库头从「文件 / 历史」扩展为「文件 / README / 历史」。
  只读一次仓库树定位根目录 README（不为多个候选文件名重复请求），再渲染。

### P4 一致性

- **刷新按钮**：异步刷新期间禁用 + 图标旋转（`aria-busy`，遵循
  `prefers-reduced-motion`）；README/历史视图下也会刷新对应内容。
- **图标体系统一**：新增 `panelIcon()` 内联 SVG 图标集，面板层（首页 storage 行、
  空态、侧栏导航）统一使用；替换了原来混用的 `⌂ ◫ ▣` 与 emoji `🔗 📂`。

### 新增：MarkdownLite（README 渲染所需，且必须防 XSS）

仓库里原本**没有**任何 Markdown 渲染器（`.md` 一直是按纯文本在记事本里打开），
因此 README 视图需要先实现一个。为满足 PROJECT_SPEC §17 / AGENTS.md §17 且不引入
marked + DOMPurify（AGENTS.md §29 要求优先原生方案），实现为「先整体转义、再做白名单
替换」：

```text
escapeHtml(整段) → 行内代码占位 → 图片/链接(协议白名单) → 强调 → 还原代码
```

原始 HTML（含 `<script>`、`<iframe>`、`<svg onload>`）在第一步就变成纯文本，
因此结构上不可能被注入；`sanitizeUrl()` 额外拦截 `javascript:` / `vbscript:` /
`data:text/html`，并先剥离控制字符以防 `java\tscript:` 绕过。

### 附带修复：notepad 的对话框判断失效

新增的 UI 结构校验脚本发现 `js/notepad.js` 用
`!document.getElementById('app-dialog')?.classList.contains('hidden')` 判断对话框是否
打开。但 `Dialog` 的根节点是**惰性创建**的，在第一次弹窗之前该元素不存在，
表达式得到 `undefined` → 判断为 false → guard 完全失效，Esc 会在对话框打开时
被记事本吞掉。改为新增 `Dialog.isOpen()` 并调用它。

## 为什么改

用户反馈首页「感觉很笨拙」。根因不是缺少样式，而是首页**没有承担入口职责**：

1. 零状态不给出下一步动作；
2. 已挂载仓库之外的信息一律不可见，用户不知道自己有什么；
3. 三个统计卡里有一个是冗余派生值，占用了最显眼的位置；
4. 空态文案三套并存，且「此文件夹为空」会在搜索无结果时误导；
5. 图标三套视觉语言混用。

## 测试情况

```bash
node --test tests/github-engine.test.mjs tests/worker-api.test.mjs tests/markdown-lite.test.mjs
# tests 43 / pass 43 / fail 0   （worker 27 + markdown 15 + 引擎套件 1 个聚合项）
node tests/github-engine.test.mjs
# 35 passed, 0 failed
node scripts/check-ui.mjs
# 6 个 HTML、76 个 id 引用、0 个 error
```

`scripts/check-ui.mjs` 是本轮新增的静态校验：检查重复 id、JS 引用的 id 是否存在
（考虑动态创建的 id）、三个页面的样式表层叠顺序、以及 CSS 类选择器使用情况。
它正是发现上面 notepad guard 失效的工具。

XSS 测试覆盖：原始/块级 HTML 转义、`onerror` 属性、`javascript:` 及其大小写与
控制字符变形、`vbscript:`/`data:text/html` 拦截、图片 src 白名单、代码围栏转义、
未闭合围栏、行内代码中的星号不被误判为强调。

## 遗留问题

- **未做真实浏览器 / Android 截图验证**：本轮仅做静态结构与逻辑校验，
  首页视觉、README 排版、44px 触达与两行移动布局仍需真机确认。
- **不支持表格、任务列表、嵌套列表、自动链接**：MarkdownLite 是有意做小，
  宁可少渲染也不放开原始 HTML；如需完整 GFM 需要引入经过审计的解析器。
- **列表视图未增加「提交信息 / SHA」列**：每个文件的时间需要单独调用
  `commits?path=`，一个目录会变成 N 次 API 调用，违反 AGENTS.md §27，
  因此刻意不做。若要做，正确方案是 Worker 侧批量解析 commit tree，属于后端改动。
- **本地存储不支持二进制上传**：`LocalDisk` 只存文本，空态上传二进制文件时会
  明确拒绝并提示，而不是静默写入损坏内容。
- `css/style.css` 仍有 21 处 `!important` 与 29 个未被引用的类选择器未清理。
- 完整 UI V2 信息架构（Repository Picker、Settings 页、应用导航与目录树彻底分层）
  仍未实施。
