## 背景

用户实测一键部署时提示：

> Your GitHub authorization has expired. Please reauthorize your GitHub connection by reinstalling the Cloudflare GitHub App

## 原因分析

该提示与仓库代码无关，是 **Cloudflare 账号侧的 GitHub App 授权状态**问题。最可能的根因：
GitHub 上存在两个不同的 Cloudflare App —— 旧的 "Cloudflare Pages" 与新的 "Cloudflare Workers"。
用户此前一直按 Pages 流程操作（装的是 Pages App），而 Deploy 按钮走 Workers Builds，需要
"Cloudflare Workers" App 的授权；未装或授权过期即报此错。

## 修改了什么

双语 README 部署章节新增「部署排查（Troubleshooting）」对照表，收录四类常见报错及处理：

1. `WorkerResource.getWorkerResult … default_environment.script` —— 旧配置所致（本仓库已修复），同步 main
2. `GitHub authorization has expired` —— GitHub 侧安装/重装 **Cloudflare Workers** App、核对
   Repository access、必要时断开重连；或用 `npx wrangler login && npx wrangler deploy` 绕过 Git 集成
3. 构建命令为空 —— 到项目 Settings → Build 手动填 `node scripts/build-config.mjs`
4. `redirect_uri is not associated` —— 回调地址与部署域名需完全一致

## 为什么改

让 fork 用户遇到同类平台侧报错时有据可查，减少排查成本；同时给出 CLI 部署这条不依赖
GitHub App 授权的兜底路径。
