# 改造记录：修复 Tree 完整性与二进制上传

## 修改了什么

- Worker 检测 GitHub recursive Tree 的 `truncated` 响应，发现树不完整时拒绝写入。
- Git Tree 重写保留 `blob` 与 `commit` 条目，避免普通文件操作删除 submodule。
- 二进制数组采用分块 Base64 编码，校验字节范围并限制单文件大小。
- 前端在 JSON 请求前显式序列化 `Uint8Array`。
- 增加 operations 数量限制，并让树读取接口拒绝截断结果。
- 独立旧 OAuth token proxy 改为 410，不再转发或返回 access token。
- 网络错误后重新读取远端 HEAD，避免直接把未知提交结果当成已确认失败。

## 为什么改

原实现把可能截断的递归 Tree 当作完整快照，会在下一次写入时删除未返回文件；submodule 条目也会被过滤。二进制内容经 JSON 后可能触发参数展开错误。旧 token proxy 仍可能被独立部署，违反 HttpOnly session 架构。

`workers/operations.js`、`workers/repos.js`、`workers/github-oauth-token.js`、`js/githubdisk.js`、`tests/worker-api.test.mjs`。

## 遗留问题

网络请求在响应丢失后只能确认远端 HEAD 是否变化，尚未引入可持久化 operation id，因此同 HEAD 的极端不确定结果仍需用户刷新检查。跨仓库传输恢复流程仍需单独完善。
