# 跨仓库转移恢复与架构规范

## 修改了什么

- 为跨 GitHub 仓库 Move 增加两阶段恢复状态：目标仓库先完成一次批量 commit，源仓库删除单独执行。
- 目标 commit 成功但源删除失败时，不回滚目标、不报告完整成功，而是生成 transfer recovery 记录。
- 恢复记录包含源/目标仓库、阶段、受影响路径、错误信息和时间。
- Conflict Center 支持选择 transfer 记录，显示源仓库到目标仓库、阶段和路径摘要。
- Conflict Center 的 Reload 对 transfer 记录会重试源仓库删除；成功后清理记录，失败则保留记录。
- 普通 CAS conflict 仍保留原有 expectedHead、remoteHead 和远端重载流程。
- 更新 `AGENTS.md` 的 Workers、D1、Worker API 与最终架构说明，避免后续改动回退到 Pages-era 名称。

## 为什么改

跨仓库 Git 操作无法由单个 Git commit 原子完成。旧逻辑虽然先写目标、再删源，但源删除失败时只抛出异常，用户无法知道目标已经存在，也没有可靠的恢复入口。恢复记录可以避免重复目标写入和误删源文件，同时让用户明确处理剩余删除阶段。
