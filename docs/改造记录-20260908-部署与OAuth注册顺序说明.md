# 改造记录：部署与 OAuth 注册顺序说明

- 日期：2026-09-08
- 关联文件：`README.md`、`README_EN.md`

## 修改了什么

在双语 README 的「部署」与「GitHub 登录配置」章节补充操作顺序说明，消除「先有域名还是先有 OAuth App」的困惑：

1. 部署章节顶部新增提示：**GitHub OAuth App 不是部署的前置条件** —— 先部署拿到 `*.pages.dev` 域名，再注册 OAuth App、配置 secret、重新部署
2. 说明 Pages 部署向导的「项目名」当场决定最终域名 `https://<项目名>.pages.dev`，注册 OAuth App 无需等待
3. 明确 GitHub 对 `Homepage URL` 字段**零校验**（可先填仓库地址），`callback URL` 支持**事后修改**（同一应用内 Update，无需重建）
4. 「GitHub 登录配置」章节补充：可先用 localhost 回调注册应用开始本地开发，部署后回改 callback

## 为什么改

用户反馈「Homepage URL 是个悖论：要先在 CF 部署一遍才能知道域名」。实际不存在死锁：GitHub OAuth App 对部署而言非前置依赖，且 Homepage URL 不校验、callback 可事后修改；原文档未写清该顺序，导致误读。
