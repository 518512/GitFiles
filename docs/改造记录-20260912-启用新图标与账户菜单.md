## 修改了什么

### 1. 新增顶栏账户菜单（修复「登录后没有退出按钮」）

**问题**：退出登录**只有一个入口**——底部状态栏里的一个小按钮
（`index.html` 的 `#btn-sign-out`）。它虽然存在，但位于页面最底部、样式低调，
移动端更难发现，用户反馈「登录后没有退出按钮」。

**修复**：按 UI V2 任务单 §六（Header V2 的右侧应为「创建入口 / 会话状态 / 用户头像 / 用户菜单」）
在顶栏右侧新增账户菜单：

```text
顶栏右侧：  ＋   状态文字    (G)  ← 点击展开
                              ┌──────────────────────┐
                              │ @octocat             │
                              │ GitHub 会话已连接     │
                              ├──────────────────────┤
                              │ ⎋ 退出 GitHub 登录    │
                              └──────────────────────┘
```

实现要点：

- 头像显示 GitHub 头像（有 disk 时），否则显示登录名首字母；
  头像是外部 URL，走 `<img>` 而非 `innerHTML`，避免不可信内容注入（AGENTS.md §17）。
- 登录名来自 `/api/me` 的 `login` 字段（原来只是 `then(() => ...)` 丢弃了响应，
  现改为 `then((me) => { githubLogin = me?.login })`）。
- **提取共享的 `signOutGithub()`**：顶栏菜单与底部状态栏两个入口复用同一段逻辑，
  原先内联在事件监听里的实现不再重复。
- 未登录时菜单项置灰；`aria-haspopup` / `aria-expanded` / `role="menu"` 齐备；
  点击外部或按 Esc 关闭。
- 移动端不隐藏（这正是不该隐藏的关键操作），菜单项触达高度 44px。

### 2. 启用新图标（`docs/图标源图-20260912.png`）

按用户提供的新设计稿重做全套图标。设计内容：蓝色圆角方块 + 浏览器窗口 +
Google Drive 文件夹 + GitHub 猫头像与双向同步箭头徽章。

因为源图是**位图**（1254×1254，无 alpha，白底合成），本次不走矢量化，改为
**高质量重采样**，新增 `scripts/build-logo-from-image.mjs`。

### 3. 「边缘丝滑」是怎么做到的

用户明确要求转换后边缘丝滑顺畅。位图缩放的常见缺陷有两个，都做了针对性处理：

**(1) 恢复 alpha**

源图没有 alpha 通道，圆角外是**白底合成**，只有约 3px 抗锯齿过渡。直接缩放会得到
一圈白边。做法：

- 三通道均 ≥ 250 视为白，从画布四边**泛洪**，只标记「与边缘连通」的背景
  （避免把手绘白色区域误判为背景）；
- 对边界像素用**蓝通道偏离白底的程度**估计覆盖率 alpha
  （红通道在不透明区约 30、白底 254，但抗锯齿中间态线性度差；蓝通道 250 vs 255，
  单调且稳定）；
- 低覆盖率归零、高覆盖率补满，消除外围淡白光晕与圆角内侧的浅色缺口。

**(2) 正确的缩放**

全过程在**预乘 alpha + 线性光**空间做 Lanczos-3 重采样：

- 若在 sRGB 空间直接平均，或在**未预乘**的颜色上平均，半透明像素会把亮色混进
  边缘，产生白边/暗边——这是「边缘不丝滑」的两个根因；
- 因此先 `sRGB → 线性`，按 alpha 预乘，再做可分离 Lanczos-3（下采样时核宽按缩放比
  放大，避免混叠），最后反预乘并回 sRGB；
- 采样权重按目标尺寸预计算，8 个尺寸总耗时约 5 秒。

**(3) 按尺寸分档**

- `logo-48/72/128/180/192/512.png`：整图缩放；
- `favicon-32.png`：整图缩放（标签页能读出整体轮廓）；
- `favicon-16.png`：整图必然糊成一团，改为裁出右下角「GitHub 猫 + 同步环」徽章再缩放。

### 4. 防止两个图标来源互相覆盖

`scripts/build-logo.mjs`（上一轮自绘矢量版）与 `build-logo-from-image.mjs`
产出**同一组文件名**。为避免误执行导致静默覆盖，矢量脚本改为**默认拒绝执行**，
必须显式 `--force`：

```bash
node scripts/build-logo-from-image.mjs "docs/图标源图-20260912.png"   # 当前采用
node scripts/build-logo.mjs --force                                   # 切回矢量版
```

## 遗留问题

- **未在真实 Android 主屏 / 标签页确认**：仍建议装到主屏核对 192/512 与实际观感。
- **未做 maskable 图标**：manifest 的 `purpose` 仍为 `any`。Android 自适应图标会裁切，
  若要更好的圆形/方形表现，需要另出一版预留 40% 安全区的 maskable 图标。
- `assets/logo.svg` 现在是**内嵌 512px PNG 的 SVG**（约 424KB），不是真正的矢量。
  源图是位图，矢量化会引入失真，故未做。若需要真正的矢量源，需重新绘制。
- 上一轮的矢量脚本与 `GEOMETRY` 定义保留但已非生效来源，长期看可考虑删除。
- `docs/new_logo-original.png`、`docs/new_logo-source-2.png`（各约 1MB）为历史设计稿，
  已不参与构建。
