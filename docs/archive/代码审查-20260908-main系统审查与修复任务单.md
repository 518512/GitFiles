- 改动：模块级 `cachedUserToken`；`acquireAccessToken()` 先验证缓存（`getAuthenticatedUser`）复用；OAuth/PAT 成功后写缓存
- 验收：`signInWithGithub` 全流程（登录→建盘）**只出现一次**授权弹窗；token 失效时缓存自动失效重取

### T2 — 仓库生命周期重设计（P0-1）
- 文件：`js/githubdisk.js`（暴露 `connectExistingRepository`/`getAuthenticatedUser` 或新增 `createDisk({mode})`）、`js/contextmenu.js`（createGithubDisk 分支）、`index.html`/`404.html`（菜单文案）
- 改动：Add storage → **GitHub repo** 点击后 `Dialog.choose`：
  `Connect existing repository`（走现有 connectExistingRepository 表单）/ `Create new repository (Drive-N)`（走 createDriveRepository）；菜单项文案改 "Create or connect repository"
- 验收：正常 OAuth 登录后**不强制**创建 Drive-1；两条路径均可完成挂载；创建失败自动落到 Connect 表单（保留现有降级）

### T3 — GitHub App token 过期处理（P0-3）
- 文件：`js/githubdisk.js`、`js/app.js`
- 改动：GitHub API 调用统一 401/403 拦截 → 该盘标记 `tokenExpired` → 侧栏该盘显示重授权入口 → 点击走 acquireAccessToken 刷新盘记录；README 已知限制补 "Expire user authorization tokens" 开关指引
- 验收：手工令盘 token 失效后，UI 明确提示并一键重授权，不再出现静默失败

### T4 — 跨仓库/跨存储批量化（P1-1/P1-2）
- 文件：`js/contextmenu.js`（transferItems 各 crossDrive 分支）、`js/githubdisk.js`（新增 `collectGithubItems(sourceDiskId, items)` 只读收集 + 批量写组装）
- 改动：GitHub→GitHub：阶段① 源递归收集（listFiles/downloadFile，无 commit，含空目录 .keep）；阶段② 目标 `executeBatch` 一次性 create（1 commit）；阶段③ cut 时源 `executeBatch` 批量 delete（1 commit）。local/Google→GitHub：先收集再单批写入
- 验收：N 文件跨仓库 **copy = 目标 1 commit**；**cut = 2 commits**（目标+源）；空目录带 .keep；失败时任一侧不产生部分状态（或明确报错回滚提示）

### T5 — GitHub Pages 部署收口（P1-3）
- 文件：`.github/workflows/pages.yml`
- 改动：Upload artifact 前加 `node scripts/build-config.mjs`（Node setup 步骤）→ 产物含 `public/` 与 `js/config.runtime.js`；upload path 改 `public`；README 方式四补 CONFIG_* 注入说明（Build 变量在 Actions 用 env 传入）
