## 3. 待规划（Backlog）

按优先级排列。**P0 表示影响数据正确性或安全**。

### P-01 Conflict Center 状态机（原 T6 / P1-5）· P1

现状：只有「记录冲突 + 重新加载远端状态」。

待做：

```text
状态机：Clean / Dirty / Committing / Conflict / Error / Offline
base(common ancestor) / ours / theirs 三方对比
逐文件 diff
文本三方合并
显式覆盖（默认禁止）
跨仓库转移的可恢复状态（retry / cleanup / compensation）
```

依据：AGENTS.md §4、PROJECT_SPEC §6。

### P-02 GitHub App installation token · P1

现状：使用 OAuth **user token**，scope 为 `repo`（偏大）。

待做：

```text
GitHub App + installation token
细粒度仓库授权（替代全量 repo scope）
session 轮换与主动吊销
```

依据：PROJECT_SPEC §10、`docs/改造记录-20260912-代码审阅问题修复.md` 遗留项。

### P-08 单文件下载 95MB 上限 · P3

超过 95MB 需要 R2 中转才能真正支持。当前返回 413。

### P-09 本地存储二进制支持 · P3

`LocalDisk` 仅存文本；空态上传二进制会明确拒绝。需要 IndexedDB Blob 存储。

### P-10 MarkdownLite 能力补全 · P3

当前有意做小：不支持表格、任务列表、嵌套列表、自动链接。

取舍理由：安全优先，宁可少渲染也不放开原始 HTML。
若需完整 GFM，需引入经审计的解析器（AGENTS.md §29 要求先论证必要性）。

### P-11 UI 真机验证 · P1

本轮所有 UI 工作只做了静态结构与逻辑校验，**未做浏览器/Android 截图验证**。
需要确认：首页视觉、README 排版、44px 触达、移动端两行布局、
Android Chrome 安全区与地址栏收缩。
