# Workers 会话架构与界面迁移

## 修改了什么

- 将 GitHub Repository 的访问从浏览器直连 GitHub API 迁移到同源 Cloudflare Worker API。
- 新增 Worker HTTP 错误、session cookie、D1 repository ACL、固定 GitHub client、仓库 API 和 Git Data mutation 模块。
- OAuth code 交换后由 Worker 创建 HttpOnly session；access token 不返回浏览器。
- Worker 根据 GitHub OAuth session 获取用户和仓库权限，将仓库读写权限写入 `repository_access`。
- 新增 `GET /api/me`、仓库/分支/tree/history/file API、`POST /api/repos` 和 CAS operations API。
- 将 Git Data create/update/delete/rename/move/copy/mkdir/upload 放入 Worker；支持批量单 Tree/Commit/ref 更新、Blob SHA 复用、路径校验和冲突映射。
- 支持空仓库首次提交：`expectedHead: null` 创建 Tree/Commit/ref；并发 ref 创建返回 409。
- 前端增加 `GithubApi` 同源 client 和无网络的 `GithubPaths` 工具；移除 GitHub token、`Authorization` header、`api.github.com` 直连与 PAT fallback。
- 浏览器入口与 Service Worker 不再加载或发布旧 `js/github/` Git API engine；该目录仅作为 Node 回归测试源码。
- 新增 Worker session 状态条、显式仓库挂载/新建选择、基础多记录 Conflict Center 和移动端冲突入口。
- 重写 `docs/PROJECT_SPEC.md`、`README.md` 与 `README_EN.md` 为 Workers + D1 + HttpOnly session 架构。

## 为什么改

旧说明和实现混合了 Cloudflare Pages、独立 token proxy、浏览器 PAT、浏览器 Git Data engine 与目标安全架构。它会让 GitHub token 再次进入浏览器，并使仓库授权与 CAS 写入绕过可信服务端边界。本次迁移将 Worker 固定为唯一可信 GitHub API 边界，并让 UI 可见 session 与冲突状态。

## 测试情况

执行：

```bash
node --check js/app.js
node --check js/githubdisk.js
node --check js/github-paths.js
node --check workers/entry.js
node --check workers/repos.js
node --check workers/operations.js
node --test tests/github-engine.test.mjs tests/worker-api.test.mjs
node scripts/build-config.mjs
git diff --check
```

结果：44 项测试通过，构建和语法检查通过。

额外产物检查确认 `public/js/github/` 不存在，生产静态资源不包含旧 GitHub API client；GitHub token 不进入前端代码。Google Drive 的 OAuth Bearer header 仍存在，属于未迁移的 Google Drive 后端。

## 遗留问题

- 真实 Worker + D1 + GitHub OAuth 部署尚需在 Cloudflare 账号中创建 D1 binding、设置 secret 并执行 schema。
- 当前 session 使用 OAuth user token；GitHub App installation token、session 轮换和过期清理未完成。
- Conflict Center 暂无逐文件 diff、文本三方合并与显式覆盖操作。
- 跨 GitHub Repository Move 仍需两阶段恢复状态与 UI。
