## 修改了什么

重新设计了应用图标（Logo），并替换 `assets/` 下全部图标资源。

### 设计延续与改动

原方案的识别特征是「蓝色文件夹 + 白色菱形 + Git 分支图腾 + 多层存储」，
新图标保留这四点，但改为**自绘矢量几何**：

| 元素 | 处理 |
|---|---|
| 圆角蓝色底板 | 保留，改为竖向渐变 `#2684fc → #0a4fd8` |
| 主文件夹 + tab | 保留，tab 比例重算（宽约 70% 主体宽、高 56） |
| 白色菱形 | 保留，作为 Git 图腾底板 |
| Git 分支图腾 | 保留（一主干 + 一分支 + 三节点），线条加粗、节点放大 |
| 多存储暗示 | 由「背面大卡片 + 折角 + 内容线 + 右侧浅蓝条」简化为**右上角两张浅蓝卡片** |

简化的原因：原方案背层元素过多，在 48px 以下会糊成噪点。
背层改为「浅蓝 + 只露一角」后，在 48/128/512 都保持可辨，且不与主文件夹争重心。

### 新增：图标构建脚本

新增 `scripts/build-logo.mjs`（约 470 行），把「一份几何定义 → SVG + 全部 PNG」
变成可重复执行的流程：

```bash
node scripts/build-logo.mjs          # 重新生成全部图标
node scripts/build-logo.mjs --check  # 校验存在性、尺寸、色彩类型
```

要点：

- `GEOMETRY` 与 `COLOR` 是唯一几何/配色来源，SVG 与 PNG 都由它派生，不会各自漂移；
- PNG 使用自写的扫描线光栅化 + Node 内置 `zlib` 做 PNG 编码，**不引入任何第三方依赖**
  （AGENTS.md §29）；
- 每个输出像素做 4×4 超采样，得到平滑边缘；
- 按尺寸分三档几何：**16px** 只留文件夹 + 菱形（不画图腾，否则必糊）、
  **32px** 放大菱形与图腾、**≥48px** 完整三层。

## 为什么改

原图标资源处于**不一致**状态：

- `assets/logo-512.png` 等 PNG 仍是**旧 Google Drive 图标**（蓝色圆角方块 + 浏览器窗口
  + Google Drive 三角），但 Google Drive 支持早已移除；
- `assets/logo.svg` / `favicon.svg` 也是 Google Drive 主题（四色三角、双圆环头像隐喻）；
- 而 `docs/new_logo-original.png` 里已经有一版**新设计**（文件夹 + Git 菱形），
  但它只是放在 docs 里的位图，从未被做成资源。

即：PNG 是「更旧的版本」，SVG 是「旧的矢量版」，新设计只停留在文档里。
本次把新设计正式做成资源，并让位图与矢量同源。

顺带解决了原位图无法覆盖的问题：旧 PNG 由外部工具生成，小尺寸下细节糊成一团且无法调整；
现在改几何或颜色只需改 `GEOMETRY`，一条命令重新出全套。

过程中修掉的两个自身缺陷（靠校验与看图发现）：

1. **`folderPath` 在 `tabH > r` 时生成退化的 SVG 圆弧**（起终点重合）。
   光栅化掩盖了它，导出的矢量路径其实是错的；已重写为「先直落再圆角」。
2. **`diamondPath` 画的是平行四边形而不是菱形**，与光栅化里的
   `|dx| + |dy| <= half` 判定不一致。已改为「顶点作控制点的二次贝塞尔」，
   圆角恰好顶到原顶点，两条产出路径数学等价。

另外确认了 16 / 32 / 48 / 128 / 512 各尺寸的实际观感（逐张查看渲染结果后调整比例）。
