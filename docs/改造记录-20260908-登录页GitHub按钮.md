# 改造记录：登录页新增 GitHub 登录按钮

- 日期：2026-09-08
- 关联：`docs/改造记录-20260908-修复部署白屏与public构建.md`

## 问题现象

首页登录页只有 "Sign in with Google"，GitHub 登录入口藏在应用内
（侧边栏 Add storage → GitHub repo）。对本 fork「GitHub 仓库文件管理器」的
定位而言不合理 —— 用户无法从首页直接完成 GitHub 登录。

## 修改了什么

### 1. 登录卡片新增 GitHub 按钮

- `index.html` / `404.html`（SPA fallback 入口同步）：Google 按钮下方新增
  `#btn-sign-in-github`（GitHub octicon 图标 + "Sign in with GitHub"）
- `css/style.css`：新增 `.btn-github`（GitHub 深色 #24292f，布局参数与
  `.btn-primary` 一致，触摸目标达标）；补充两个登录按钮的 `:disabled` 视觉态
  （Google 登录流程此前禁用按钮时无视觉反馈）

### 2. 登录流程串联（js/app.js）

- `signInWithGithub()`：调用 `GithubDisk.acquireAccessToken()`（OAuth popup
  优先；token 代理不可达时内部自动降级 PAT 对话框）→ 若尚无 GitHub 存储则
  `createDisk()` 自动连接 → `showExplorer()` 进入主界面并渲染侧栏
- 错误处理：用户取消/关闭弹窗静默返回；配置缺失（`GITHUB_CLIENT_ID` 为占位）
  与代理不可达等错误经 `showLoginError` 显示在登录页（文案含配置指引）
- 按钮点击期间禁用，结束后恢复

### 3. 文档

- 双语 README Quick start 更新：首页两种登录入口说明

## 为什么改

fork 的核心场景是 GitHub 存储，首页却只能登录 Google，形成定位与入口的错位；
且所有底层能力（OAuth/PAT 登录、建盘、错误降级）均已存在，仅需串联。

## 涉及文件

- `index.html`、`404.html`、`css/style.css`、`js/app.js`、`README.md`、
  `README_EN.md`、`js/app-version.js`

## 测试情况

- `node --check js/app.js` 通过；引擎回归 32/32 通过
- 调用时序核对：`GithubDisk.init()`（popup message 监听）先于 `bindEvents()`
  执行，首页发起的 OAuth 回调可被接收
- 端到端实测待部署后验证（依赖用户已配置 `GITHUB_CLIENT_ID` 与
  `GITHUB_CLIENT_SECRET`）

## 遗留问题

- 登录页 `CONFIG.CLIENT_ID === 'YOUR_CLIENT_ID...'` 的旧占位检测已与
  config.js 模板化后的空值占位不匹配（Google 按钮不会被禁用），登录时会由
  Google 库自身报错 —— 后续可统一为空值检测
