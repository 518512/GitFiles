# 改造记录：一键部署 Workers 化，修复部署报错

- 日期：2026-09-08
- 关联：`docs/改造记录-20260908-修复CF部署路径.md`（其中"按钮为备选路径"的结论被本轮推翻并纠正）

## 背景

用户质疑："你是不是对一键部署有什么误解？为什么其他项目都可以实现？"

核实结论：**用户是对的**。Deploy to Cloudflare 按钮（2024 年起）底层基于 **Workers Builds**，只按
Workers 标准解析 `wrangler.jsonc`；其他项目一键能成功，正是因为它们用的是 Workers（± Static
Assets）配置。此前报错 `WorkerResource.getWorkerResult: response missing default_environment.script`
的真正原因是我方的配置错误：`wrangler.jsonc` 一边保留 Pages 字段（`pages_build_output_dir`），
一边塞入了**缺少 `directory` 字段**的 `assets` 块 —— 按钮按 Worker 解析时既无 script 又无有效
assets，必然报错。上一轮"把按钮降级为备选"是对症不对因。

## 修改了什么

### 1. 部署载体迁移：Pages → Workers + Static Assets

- `wrangler.jsonc` 重写为 Workers 标准配置：`main: workers/entry.js` +
  `assets: { directory: "./", binding: "ASSETS", not_found_handling: "404-page" }` +
  `build.command`
- 新增 `workers/entry.js`：Worker 入口
  - `POST /api/github/oauth/token`：同源 token 交换代理（逻辑与 serve.py /
    workers/github-oauth-token.js 一致：reachability-check 直通 / 带_secret 原样转发 /
    注入 `GITHUB_CLIENT_SECRET`，缺失返回 `misconfigured_proxy`）
  - `OPTIONS` 预检、非 POST 405、其余 `/api/*` 404
  - 其他路径 → `env.ASSETS.fetch`（静态资源 + 404.html 兜底）
- 新增 `.assetsignore`（语法同 .gitignore）：仅发布前端站点文件，排除
  docs/tests/scripts/serve.py/workers/wrangler.jsonc/README 等
- **删除 `functions/api/github/oauth/token.js`**（Pages Functions 专属约定，Workers 模式下
  不生效；其职责由 `workers/entry.js` 承担）
- 域名从 `*.pages.dev` 变为 `gitfiles.<子域>.workers.dev`

### 2. 文档同步

- 双语 README：部署方式重排回**一键部署（方式一，主推）**；Git 连接（方式二）降为手动版；
  CLI（方式三，改为 `npx wrangler deploy`）；GitHub Pages（方式四）；token 代理表第一行改为
  "Worker 内置代理"；回调地址表、目录结构图、差异表、架构描述同步更新
- 修复英文版 README_EN.md 在此前多轮编辑中丢失的整段内容（Tests / Architecture / Project
  structure / Differences / Documentation / Known limitations / Acknowledgements），以中文版为
  基准完整重写，章节 1:1 对齐（21+1 节）
- 中文版补齐「OAuth 应用描述」节（此前仅英文版有）
- AGENTS.md §9：目标架构注记 —— Pages 载体演进为 Workers + Static Assets，
  "Pages Function"字样理解为"Worker 内的 API 处理"，原则不变

## 为什么改

让一键部署像其他项目一样开箱可用（Workers 是按钮原生支持的形态）；同时 Pages 产品线已冻结，
Workers + Static Assets 是 Cloudflare 官方演进方向，长期维护成本更低。

## 涉及文件

- 新增：`workers/entry.js`、`.assetsignore`
- 删除：`functions/api/github/oauth/token.js`
- 修改：`wrangler.jsonc`、`README.md`、`README_EN.md`、`AGENTS.md`

## 测试情况

- `workers/entry.js` 语法检查通过；引擎回归 32/32 通过
- 前端兼容性核对：`ensureTokenExchangeReachable` 的探测请求期待 JSON 对象响应 → Worker 返回
  `{ok:true, proxy:'worker'}` ✓；未配 secret 时 `misconfigured_proxy` 的 `error_description`
  会被 `exchangeCodeForToken` 提取显示 ✓（与原 Pages Function 契约一致）
- SW 不缓存 `/api/*` 的既有规则不变（AGENTS §16）
- 待部署实测：按钮流程 + `gitfiles.<子域>.workers.dev` 域名下的端到端登录

## 遗留问题

- D1 会话（AGENTS §3/§10 的 token 出 localStorage 目标）仍在规划中，不受本次迁移影响
- Workers 自定义域用户需在 `workers/entry.js` 的 `isAllowedOrigin` 追加其域名（同源调用不受影响）
