## 为什么改

### 脱离 fork 的经过

通过 GitHub 的 **Settings → General → Danger Zone → Leave fork network** 完成
（仓库 12MB，满足「公开、小于 1GB、无子 fork」三个前提条件）。

该操作**不可逆**，且会丢弃 fork 网络关联的 issues / PR / wiki / stars / watchers
（**commit 历史完整保留**，这是关键——血缘可追溯，致谢才有据可依）。

### 为什么要补致谢

脱离 fork 网络后，GitHub 页面上「forked from」的链接会消失。这意味着
**上游归属的唯一载体只剩 README**。如果不显式署名，原作者的贡献就从项目页面上
彻底不可见了。所以这不仅是礼貌问题，而是脱离 fork 之后必须做的补偿动作。

同时这正是我在 `docs/架构现状-20260912.md` §3.3 里列为待办的
「上游归属说明」一项，本次一并完成。

### 为什么修正 D1 命令

用户实际按 README 操作时，凭直觉在 Cloudflare 控制台执行 SQL——这条路 README
完全没写。补上后顺便发现原文的 wrangler 命令缺 `--remote`，是个会静默改错库的坑。
