# 改造记录 20260912 PROJECT_SPEC 校准与 OAuth 安全件备注

## 修改了什么

### 1. `workers/github-oauth-token.js` 的文件内备注

该文件没有任何模块引用，从外部看像死代码，实际是**安全替代件**。
原注释只有两行，本轮扩充为完整的意图说明（文件从 21 行增至 43 行）：

- **历史**：上游把 token 交换放在这个端点，结果直接返回浏览器，token 因此进入前端存储
- **现在**：OAuth 由 `workers/entry.js` 处理，token 只写入 D1，浏览器只拿 HttpOnly cookie
- **为什么保留**（三个理由）：防止旧部署泄露 token / 用 410 表明端点永久迁移而非 404 不存在 /
  留下可追溯的迁移痕迹，避免后来者"顺手实现"一个返回 token 的版本
- **约束**（显式三条）：不要删除、不要在此实现交换、不要把 `access_token` 放进响应
- 关联规则指向 `AGENTS.md` §3/§5 与 `PROJECT_SPEC` §3.1

## 为什么改

- 规格是「应当实现成什么样」的契约。**规格与代码不一致比没有规格更危险**——
  上一轮 AGENTS.md 里过时的路由表就是例子：照着实现会直接 404。
- `github-oauth-token.js` 的问题不是缺注释，而是**注释没说明"不要删"**。
  一个无引用的文件迟早会被当死代码清掉，而那会造成 token 泄露风险。
