# 改造记录：修复 Workers 部署白屏（入口重定向死循环）与 public/ 构建结构

- 日期：2026-09-08
- 关联：`docs/改造记录-20260908-一键部署Workers化.md`

## 问题现象

部署到 `https://cf-gitfiles.ijays.workers.dev/` 后页面白屏。Worker 指标完全健康
（0 错误、asset 请求 9.54k、Cache 命中 95.2%、CPU 434µs），`GET /` 返回 200 的
index.html —— 服务端正常。

## 根因（curl 实证）

Workers Static Assets 的 `auto-trailing-slash` HTML 规范化会把 `/index.html`
**307 重定向到 `/`**（`curl -D- /index.html` → `HTTP/2 307 location: /`）。
而前端有两处"入口规范化"逻辑会把 `/` 跳到 `/index.html`：

1. `index.html` / `404.html` 顶部内联脚本：`barePath === '/'` 时
   `location.replace('/index.html')`
2. `js/base-path.js` 的 `ensureEntryPath()`（`needsEntry = bare === '/' || …`）
   与 `redirectBareRootIfNeeded()`（`bare !== '/' && !(root && bare === root)` 中
   bare === '/' 继续放行）

于是形成死循环：`/` → JS 跳 `/index.html` → assets 307 回 `/` → JS 再跳 ……
浏览器放弃执行 → 白屏。每次循环 asset 都命中缓存，与"0 错误 + 高命中率"的
指标完全吻合。GitHub Pages 上无此 307 规范化，所以从未暴露。

## 修改了什么

### 1. 断开重定向循环（保留 GitHub Pages 行为）

- `index.html` / `404.html` 内联脚本：`barePath === '/'` 不再跳转；仅
  `root && barePath === root`（如 GH Pages `/GitFiles`）时才 replace 到
  `${root}/index.html`
- `js/base-path.js`：
  - `ensureEntryPath()`：`needsEntry` 去掉 `bare === '/'` 分支
  - `redirectBareRootIfNeeded()`：改为 `if (!(root && bare === root)) return false`

### 2. 构建产物迁移到 `public/`（采纳官方推荐结构）

- `scripts/build-config.mjs` 重写：重建 `public/`（复制 10 个前端文件 +
  css/js/assets 目录，排除 `config.local*.js`）→ 生成 `public/js/config.runtime.js`
- `wrangler.jsonc`：`assets.directory: "./public"`；
  `not_found_handling: "single-page-application"`（SPA 深链直接 200 返回
  index.html，替代 404.html 中转，前端 router 解析 `/Drive-1/...`）
- 删除 `.assetsignore`（public/ 产物天然干净，不再需要排除清单）
- `.gitignore` 增加 `public/`（构建产物不入库）

### 3. 其他

- `js/app-version.js` 版本戳更新（SW 缓存强制刷新）

## 为什么改

- 白屏是部署不可用级别的问题，根因是托管规范化与前端入口跳转互相打架
- `public/` 结构是 Cloudflare 官方推荐的 assets 布局；此前以仓库根为
  directory 依赖 `.assetsignore` 打补丁，不干净且容易误伤

## 涉及文件

- 修改：`index.html`、`404.html`、`js/base-path.js`、`scripts/build-config.mjs`、
  `wrangler.jsonc`、`.gitignore`、`js/app-version.js`
- 删除：`.assetsignore`

## 测试情况

- 路径判定冒烟 4 场景全部符合预期：
  - Workers `/index.html` → base=""，无跳转
  - Workers `/` → redirectBareRoot=false，无跳转
  - GH Pages `/GitFiles/` → base="/GitFiles"，replace → `/GitFiles/index.html`（原行为保留）
  - Workers 深链 `/Drive-1/My%20Drive/` → base=""，交由 router
- `public/` 构建验证：48 个文件，`public/js/config.runtime.js` 生成，
  `config.local.js` 未混入
- 引擎回归 32/32 通过

## 遗留问题

- **Git 集成 / 一键部署必须在项目 Settings → Build 填写**
  `node scripts/build-config.mjs`，否则 public/ 不会生成、assets 上传失败
  （报错信息会明确提示 directory 缺失）；留空的容错性比根目录方案差，换取了
  标准结构
- 部署实测待用户重新 deploy 后确认（本地 curl 验证 `/` 与深链应在修复合入
  并重新部署后恢复）
