## 一、首页重构为工作区入口

**重构前的问题**：

1. 首页只渲染「已挂载」的 storage，用户 GitHub 上有什么完全不可见；
2. 零状态只有一句「尚未挂载存储」，**内容区没有任何主行动按钮**——
   唯一带按钮的欢迎空态只在 `level !== 'home'` 时显示，首页根本走不到；
3. 三个统计卡片里「已挂载存储」恒等于前两者之和，是虚荣指标；
4. `overview-empty`、`no-storage-state`、`overview-summary` 三套空态文案职责重叠。

**重构后**：

```text
概览                                        [添加存储]
──────────────────────────────────────────────────────
最近访问
  ▸ owner/repo    GitHub · 私有 · 分支 main · docs/    3 分钟前

已挂载存储              2 个仓库 · 1 个本地存储 · 3 个已挂载
  ▸ owner/repo    GitHub · 私有 · 分支 main
  ▸ 本地存储
```

- **最近访问**：`localStorage` 记录 `disk id + 时间 + 最后停留目录`（上限 6 条）
- 统计降级为标题旁一行小字
- 按用户确认：**不显示**未挂载的「可添加仓库」，首页只展示已挂载项
- **首页不发起任何额外 API 请求**（不为显示每个仓库的提交时间而逐仓库读 tree）

**顺带合并侧栏语义**：原「概览」与「仓库」两个导航项其实渲染同一个面板、
只切 `overviewMode`，已合并为单一「概览」并移除该状态。

**仓库工作区**：空目录空态带「上传文件 / 新建文件」动作（按场景区分文案，
搜索无结果/回收站/README 各有对应提示，不再错误显示「此文件夹为空」）；
新增 **README 页签**（文件 / README / 历史）。

## 二、MarkdownLite：README 渲染的安全实现

仓库里原本**没有任何 Markdown 渲染器**（`.md` 一直按纯文本在记事本打开），
README 视图需要先实现一个。为满足 `PROJECT_SPEC` §8 / `AGENTS.md` §17
且不引入 marked + DOMPurify（§29 要求优先原生方案），实现为
**「先整体转义、再做白名单替换」**：

```text
escapeHtml(整段) → 行内代码占位 → 图片/链接(协议白名单) → 强调 → 还原代码
```

原始 HTML（含 `<script>`、`<iframe>`、`<svg onload>`）在第一步就变成纯文本，
因此结构上不可能被注入。`sanitizeUrl()` 额外拦截 `javascript:` / `vbscript:` /
`data:text/html`，并先剥离控制字符以防 `java\tscript:` 绕过。

15 项测试覆盖：原始/块级 HTML、`onerror`、大小写与控制字符变形的
`javascript:`、`vbscript:`/`data:text/html`、图片 `src` 白名单、代码围栏、
未闭合围栏、行内代码中的星号不被误判为强调。

> 写测试时修正了 4 个**过严的断言**：最初用「输出里是否含 `onerror=`」判断，
> 但转义后的可见文本 `&lt;img onerror=...&gt;` 本就该原样展示，不是漏洞。
> 改为检查「真实标签内部」与「URL 属性」。

## 三、账户菜单（修复「登录后没有退出按钮」）

**问题**：退出登录**只有一个入口**——底部状态栏里的小按钮。它存在，但位置最底部、
样式低调，移动端很难发现，用户反馈「登录后没有退出按钮」。

**修复**：按 UI V2 任务单 §六在顶栏右侧新增账户菜单：

```text
顶栏右侧：  ＋   状态文字   (G) ← 点击展开
                            ┌────────────────────┐
                            │ @octocat           │
                            │ GitHub 会话已连接   │
                            ├────────────────────┤
                            │ ⎋ 退出 GitHub 登录  │
                            └────────────────────┘
```

- **提取共享的 `signOutGithub()`**：顶栏菜单与状态栏两个入口复用同一逻辑
- 头像走 `<img>` 而非 `innerHTML`（外部 URL，按 §17 不能当可信内容拼进 DOM）
- `/api/me` 的响应原先被丢弃，现记录 `login` 与 `avatar`
- 未登录时菜单项置灰；`aria-haspopup` / `aria-expanded` / `role="menu"` 齐备；
  点击外部或 Esc 关闭

### 账户菜单被遮挡（真 bug）

**根因**：`.ribbon` 有 `overflow: hidden`，而菜单面板是挂在它内部的
**绝对定位弹出层**，展开即被父级裁掉。

**修复**：`.ribbon` 改 `overflow: visible`，横向溢出仍由内部的
`.address-bar` / `.breadcrumbs`（`overflow-x: auto`）收敛。

> 教训：给容器加 `overflow: hidden` 会连带裁掉**所有**绝对定位子元素。

### 头像

原先只显示登录名首字母——因为 `/api/me` 只返回 `login`，头像靠本地 disk 元数据猜，
而该字段仅在**挂载仓库后**才存在。

**修复**：`sessions` 增加 `github_avatar`，建 session 时写入 `user.avatar_url`。

**兼容旧库**：该列是**可选**的。为不让未执行 migration 的部署整体 500：

- `requireSession` 先按新列查询，**失败则回退旧列集合**
- `/api/me` 在列为空时用 `avatars.githubusercontent.com/<login>` 推导
- 前端 `<img>` 的 `onerror` 再回退到首字母

因此**不执行 migration 也能正常使用**。

## 四、应用图标

### 第一版：自绘矢量（后被取代）

自绘了「蓝色文件夹 + 白色菱形 + Git 分支图腾 + 多层存储」的矢量图标，
并新增 `scripts/build-logo.mjs`（一份 `GEOMETRY` 同时产出 SVG 与全部 PNG，
PNG 用自写扫描线光栅化 + Node 内置 `zlib`，不引入依赖）。

过程中修掉两个**自身缺陷**（靠校验与看图发现）：

1. **`folderPath` 在 `tabH > r` 时生成退化的 SVG 圆弧**（起终点重合）。
   光栅化掩盖了它，导出的矢量路径其实是错的。
2. **`diamondPath` 画的是平行四边形而不是菱形**，与光栅化里的
   `|dx| + |dy| <= half` 判定不一致。已改为「顶点作控制点的二次贝塞尔」，
   圆角恰好顶到原顶点，两条产出路径数学等价。

### 第二版（当前生效）：用户提供设计稿

用户提供了新的设计稿（`docs/图标源图-20260912.png`，1254×1254，
**无 alpha、白底合成**，圆角外约 3px 抗锯齿）。改为**高质量重采样**，
新增 `scripts/build-logo-from-image.mjs`。

「边缘丝滑」的针对性处理：

1. **恢复 alpha**：对画布四边做**泛洪**标记连通背景（避免把画面里的白色
   误判为背景），再用**蓝通道偏离白底的程度**估计覆盖率。
   红通道**不可用**——不透明区红仅约 30，抗锯齿中间态线性度差。
   低覆盖率归零、高覆盖率补满，消除外围白晕与圆角内侧缺口。
2. **正确的缩放**：全过程在**预乘 alpha + 线性光**空间做 Lanczos-3。
   若在 sRGB 空间平均、或对未预乘的颜色平均，半透明像素会把亮色混进边缘，
   产生白边/暗边——这是「边缘不丝滑」的两个根因。
3. **按尺寸分档**：16px 整图必糊，改为裁出右下角「GitHub 猫 + 同步环」徽章再缩放。

矢量脚本改为**默认拒绝执行**（需 `--force`），防止两个产出互相覆盖。

> **发现的不一致**：原 `assets/logo-512.png` 等 PNG 仍是**旧 Google Drive 图标**
> （该支持早已移除），`logo.svg` 也是 Google Drive 主题，而新设计只躺在 docs 里。

## 五、文案与合规

### 首页与首屏文案对齐定位

```diff
- 一个全屏、快速、安全的本地与 GitHub 仓库文件管理器。
+ 把 GitHub Repository 当作云端文件系统：浏览、上传、编辑，并以正确的 Git 历史提交。
```

同步 `site-config.js` 的 tagline 与 `app.js` 首页三条文案；新增**静态**

### 隐私政策写了不存在的 Google 集成（合规问题）

`privacy.html` 是**法律文本**，但仍声明已移除的能力：

```text
「Google Identity Services（登录）」「Google Drive API」   ← 列为第三方服务
「我们不会收到你的 Google 或 GitHub 密码」
撤销权限链接 → myaccount.google.com/permissions
```

对开源项目尤其容易误导使用者的授权判断。已逐条更正（撤销链接改到 GitHub
已授权应用页面），仅保留一句「Google Drive 支持已移除」说明能力边界。

## 七、部署说明修正

README 的 D1 初始化原只有 wrangler 一条路径，且**缺 `--remote`**：

```bash
# ❌ 原文：只改了本地 .wrangler/state 副本，线上毫无变化
npx wrangler d1 execute <database-name> --file=workers/schema.sql

# ✅ 现在
npx wrangler d1 execute <database-name> --remote --file=workers/schema.sql
```

补全为三条路径（Dashboard 控制台 / wrangler CLI / 已有部署增量升级），
并说明已有生产库应只执行 `ALTER TABLE ... ADD COLUMN checked_at INTEGER`
而不是整个 schema（`DROP TABLE` 会清空 session、强制全员重登）。

## 遗留问题

- **未在真实 Android 主屏 / 浏览器标签页确认图标观感**（16/32/192/512）。
- **未做 maskable 图标**：manifest 的 `purpose` 仍为 `any`；
  Android 自适应图标裁切需要另出预留 40% 安全区的版本。
- `assets/logo.svg` 现在是**内嵌 512px PNG 的 SVG**（约 424KB），不是真矢量。
  源图是位图，矢量化会引入失真，故未做。
- MarkdownLite 有意做小：不支持表格、任务列表、嵌套列表、自动链接。
- 本地存储只支持文本，二进制上传会被明确拒绝。
- `docs/new_logo-original.png`、`new_logo-source-2.png`（各约 1MB）为历史设计稿，
  已不参与构建。
- **LICENSE 仍是唯一阻塞项**：上游未声明 LICENSE，本项目继承该无许可状态；
  取得授权前不可再分发。
- **fork 仍未解除**：需在 GitHub 网页操作 Settings → General → Danger Zone →
  Leave fork network。
- **GitHub 仓库 About 描述与 Homepage 需手动改**（无法通过 git 操作）：
  description 仍是上游文案且含已移除的 Google Drive；homepage 指向上游 demo。
