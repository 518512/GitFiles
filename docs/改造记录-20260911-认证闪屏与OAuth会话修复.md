# 改造记录：认证闪屏与 OAuth 会话修复

## 修改了什么

- 页面初始将登录界面隐藏，由认证检查完成后再显示登录页或文件管理器。
- Worker session 检查使用共享 Promise，避免初始化和用户操作并发触发多次检查。
- OAuth 认证流程使用共享 Promise，避免重复弹出授权窗口。
- OAuth 广播通道忽略其他登录尝试的旧 state，不再错误中断当前认证。
- token exchange 明确携带同源 Cookie，并由 Worker 返回 `Access-Control-Allow-Credentials`。
- 拒绝跨源 token exchange 配置，避免授权码交换成功但 HttpOnly session Cookie 写入错误域名。
- 保留 exchange 后 `/api/me` 二次验证，只有 Worker session 真正建立才算登录成功。

## 为什么改

刷新时 HTML 中登录页默认可见，而 `/api/me` 尚未完成，导致认证页面闪现。多个标签页或旧 popup 的 BroadcastChannel 消息还可能干扰当前授权。跨源 token exchange 无法为当前应用建立同源 session Cookie，会表现为 popup 关闭后仍未登录。
