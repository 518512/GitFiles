## 二、搜索框与排序菜单下方的多余横线

**根因**：`css/style.css` 给 `.file-tools` 设了

```css
.file-tools {
  background: #fff;
  border-bottom: 1px solid var(--win-border);
  padding: 4px 10px;
}
```

历史上 `.file-tools` 是**独立的一条工具栏**，所以有白底和下边框。
UI V2 把它并入 `.ribbon` 后，这两个属性就变成"在工具栏内部画一条横线"。

**修复**：在 V2 层显式复位（`background: transparent; border-bottom: 0; padding: 0`），
不动历史样式。同时把 `.search-box` / `.sort-select` 改为扁平风格
（去掉历史边框与白底，仅 hover/focus 给反馈）。

## 三、顶栏重复文案

顶栏的 `#header-repo-state` 显示 `owner/repo · 分支`，但**正下方的仓库头
（`.repository-header`）已经在显示同一信息**，属于同屏重复。

**修复**：`display: none`（节点保留，不改会话逻辑）。
同时把状态栏/账户菜单作为会话状态的表达位置。

## 四、视图切换合并为单按钮

原「大图标 / 详细信息」是两个并排按钮，占两个控件位。

**修复**：合并为单一 `#btn-view-toggle`，**图标表示「点击后会切到的模式」**：

```text
当前 list → 显示网格图标，title/aria-label = 切换到详细信息
当前 grid → 显示列表图标，title/aria-label = 切换到大图标
```

**移动端默认 list** 的修正：原代码直接改 `state.view`，**没走 `setView`**，
导致按钮图标与 `aria-label` 不同步；且只在初始化判断一次，旋转屏幕不跟随。
改为 `setView(...)` + `matchMedia` 断点监听，并新增 `viewPinnedByUser`——
**用户手动切过后不再自动覆盖其选择**。

## 五、返回上一级：两次修正才对

### 第一次尝试（错误）

做成了工具栏里一个**独立的箭头按钮**，放在面包屑左侧。

用户指出：位置与形态都不对——文件管理器的常识是
「进入子目录后，**列表最上方**出现 `..` 项」，而且单独的箭头图标表达不了"回到上一级"。

### 第二次（当前实现）

- **位置**：列表 / 网格的**最上方第一个条目**
- **形态**：图标是**文件夹**，名称为 `..`
- **位置判断** `folderParentId()`：

  ```text
  GitHub / Drive   文件夹 id 即路径："a/b" → "a"，"a" → 根
  本地存储         id 是生成的 entryId，改从 disk 元数据或 breadcrumbs 推导
  （三种磁盘根 id 均为 'root'）
  ```

- 根目录**不显示**，避免永远不可点的入口
- 可访问性：`role="button"`、`tabIndex`、Enter/Space、`title`、`:focus-visible`
- 连带修复：空目录但可返回上级时**不再显示「此文件夹为空」**——
  空态是独立容器会把列表遮住，且与 `..` 行自相矛盾

### 第三次：图标一致性

首次实现用了**自绘的灰色 SVG 文件夹 + 蓝色箭头角标**，用户反馈「有些突兀」。

核对后确认：普通目录项的图标是 **emoji `📁`**（`githubdisk.js` / `localdisk.js`
里 `icon: '📁'`），而 `..` 行是单色 SVG —— 同一列表中视觉语言割裂。

改为复用**完全相同**的 emoji，并套用同一尺寸类
（列表 `file-icon-wrap--small` → 1rem；网格不传 → 2.2rem），保证字号也一致。
语义由 `..` 名称 + `title` + `aria-label` 承担，删掉了只为 SVG 方案准备的三条样式。

> 教训：为"更好辨识"引入新视觉元素前，**先确认同类元素已经用什么**。
> 一致性优先于局部优化。

## 六、移动端仓库头换行与页签竖排

**现象**：仓库头的 `owner/repo` 在窄屏换行；右侧「文件 / README / 历史」
两个中文字**逐字竖排**。

**根因（同一 flex 缺陷的两面）**：

```text
.repository-name   用了 overflow-wrap: anywhere → 允许任意字符处断行
.repository-tabs   没有 nowrap / flex-shrink:0 → 作为 flex 子项默认可收缩，
                   窄屏被压到比文字还窄，中文便逐字换行
.repository-heading 没有 flex:1 1 auto → 长仓库名不收缩而是撑开头部分挤页签
```

**修复**：收缩模型改为「标题可收缩、页签不收缩」：

```css
.repository-heading  { flex: 1 1 auto; min-width: 0; }
.repository-heading > div { min-width: 0; }   /* min-width:0 是 ellipsis 生效的必要条件 */
.repository-name     { white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }
.repository-tabs     { flex: 0 0 auto; flex-wrap: nowrap; }
.repository-tab      { white-space: nowrap; flex: 0 0 auto; }
```

把 `overflow-wrap: anywhere` 换成 `nowrap + ellipsis`：**截断优于换行**。

**移动端精简**：隐藏 `◫` 装饰图标、仓库名 19→15px、meta 12→11px、
页签 13px/36px、内边距与间距收紧。

> 关于「库名按区域自动缩放字号」：现代 CSS **没有**纯声明式的
> 「按容器宽度缩放字号」（`text-box` / container queries 都不做字号缩放），
> 需 JS 测量。采用**固定区域 + 省略号截断**，永不换行且不引入重排。

## 七、移动端隐藏面包屑

用户指出「仓库名 › 子目录」占用过多顶部空间。

**修复**：移动端隐藏 `.ribbon .address-bar`。依据是信息已有更合适的载体：

```text
当前目录是什么   列表里的 ".." 行 + 列表内容
所在的仓库       仓库头（仓库名 / 分支 / 公开私有）
如何跳转         ".." 行、侧栏目录树、品牌按钮回首页
```

移动端布局随之简化为：

```text
第 1 行  导航 · 品牌 · [弹性] · 刷新 · ＋ · 头像
第 2 行  搜索 · 视图切换
```

> 此前曾把面包屑类比成「浏览器的地址栏」来说明它不该隐藏——**这个类比不成立**：
> 浏览器地址栏可以直接编辑跳转，这里的面包屑做不到。
