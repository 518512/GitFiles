# 改造记录：部署工作流调整为 Fork → 连接 → Sync upstream 主推

- 日期：2026-09-08
- 关联：`docs/改造记录-20260908-一键部署Workers化.md`

## 背景

用户指出开源项目的合理工作流应为「用户 GitHub Fork（保留上游关系）→ Cloudflare
绑定该 fork → 用户 Sync upstream → 自动部署」，而不是 Deploy Button 那种由
Cloudflare 再复制一个仓库副本的模式 —— 副本不是 fork，没有 Sync fork 按钮，
更新链路断裂。

## 修改了什么

双语 README 部署章节重排：

- **方式一（主推）**：Fork → Workers & Pages Import a repository 连接用户 fork →
  日常经 GitHub「Sync fork」自动同步部署；含完整步骤（build command 必填说明、
  `CONFIG_*` 用 Text 类型 / `GITHUB_CLIENT_SECRET` 用 Secret 类型的原因）
- **方式二（降级）**：Deploy to Cloudflare 按钮 —— 明确定位为"快速试用"，
  并说明其副本非 fork、无法 Sync fork 的局限
- 方式三（CLI）、方式四（GitHub Pages）不变

## 为什么改

让文档与开源项目的长期使用体验对齐：fork 关系是自动跟随上游更新的前提，
Deploy Button 的复制模式恰恰破坏这个前提。
