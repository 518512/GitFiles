# 改造记录 20260912 交互问题排查与修复

> 用户反馈「这个交互方面好像还有很多问题」。系统排查选中、打开、多选操作条等核心链路，
> 确认 4 个问题，全部修复。

## 已确认并修复的问题

### A. 移动端无法打开文件（最严重）

**根因**：列表 / 网格项只有两条打开路径，都依赖 `dblclick`：

```js
item.addEventListener('click', (event) => selectFile(file.id, event));   // 选中
item.addEventListener('dblclick', () => openFile(file));                 // 打开
```

**移动端 `dblclick` 不可靠**（触屏上双击语义怪异，且这些 DOM 项不整合 tap 手势），
出现在移动端时 `openFile` 永远不触发 —— 轻点只选中、没有打开方式。
对一个「Android 优先」的应用，这等于文件内容在触屏上打不开。

**修复**：`handleItemTap` 按设备分发：

```text
桌面端（>768px）    单击选中，双击打开（行为不变）
移动端（≤768px）    单击即打开文件 / 进入文件夹；长按仍弹上下文菜单
修饰键（ctrl/shift） 保留多选（两种设备都生效）
```

> 移动端「轻点打开 + 长按菜单」是文件管理器的通用契约，不会与选中冲突。

### B. 每次点选都整表重渲染

**根因**：`selectFile()` 末尾调用 `renderCurrentView()`，而它把整个 grid/list
`innerHTML` 重建。多选、大目录下卡顿、滚动位置被重置。

**修复**：改为**增量**——只切换被点项自己的 `selected` 类：

```js
function updateItemSelectedState(id, selected) {
  [$('#file-grid'), $('#file-list')].forEach((root) => {
    const el = root?.querySelector(`[data-id="${CSS.escape(id)}"]`);
    el?.classList.toggle('selected', selected);
  });
}
```

外部的整表重渲染（排序 / 搜索 / 刷新）不受影响。

### C. 移动端多选「复制 / 移动」是死路

**根因**：底部操作条多选时：

```js
if (files.length > 1) {
  showStatus('多选复制和移动请使用右键菜单中的批量操作');
  return;
}
```

但**移动端没有右键菜单** → 多选复制/移动永远走不到。

**修复**：多选 copy / cut 把**整组写入剪贴板**（新增 `ContextMenu.setClipboardMode`），
而后 `paste`（`transferItems`）本来就支持多项目批量 —— 补上入口即可，不再有提示死路。

### D. `..` 返回上级行被当成可选文件

`selectFile` 收到 `data-id === '__go_up__'` 时会把它塞进选中集合并触发整表重渲染。
**修复**：在 `selectFile` 开头对 `__go_up__` 与「文件中不存在」的 id 一律 return。
