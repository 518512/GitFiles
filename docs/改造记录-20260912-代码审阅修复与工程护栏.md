## 二、CSS 层叠顺序：历次 UI 改动反复回退的根因

**现象**：历次「界面: 收敛添加按钮 / 缩小按钮 / 对齐工具按钮」的提交改完就回退。

**根因**：`js/base-path.js` 用 `appendChild` 动态注入 `style.css`，而 `index.html`
静态写的是 `ui-v2.css`，实际层叠顺序变成：

```text
ui-v2.css（设计令牌 / V2 覆盖）  ← 先加载，被覆盖
style.css（3400 行历史样式）     ← 后加载，最终生效
```

**即整个 V2 设计层一直被历史样式压住**。在 `ui-v2.css` 里加规则根本赢不了
`style.css` 的 `!important` 与更高特异性。

**修复**：

- 三个页面统一为 `style.css` → `ui-v2.css` 的静态顺序（消除首屏 FOUC）
- `bootstrapHeadAssets()` 负责补 `?v=` 并在末尾重新追加 `ui-v2.css`，保证 V2 最后层叠
- `ui-v2.css` 按小节重写，消除**三个互相打架的 `.ribbon` 块**与**两个重叠的媒体查询**

## 三、两层样式表冲突：工具化排查

层叠修好后又出现一批「多余横线 / 割裂色块」：`style.css` 的规则是在**旧布局**下写的，
元素被搬进新结构后，旧的定位与装饰属性仍然生效。

新增 **`scripts/audit-css.mjs`**：列出给定类在两层样式表里的全部规则
（来源、行号、是否 `@media`、是否 `!important`），并标出「历史层胜出、V2 层未复位」的属性。

### 工具本身的两个缺陷（先修工具，再修样式）

1. **误报**：原判定是「V2 是否出现同名属性」，导致 `display` / `flex` 这类
   「两层都设、V2 以更高特异性胜出」的属性被误报。改为按 **(特异性, 层叠顺序)**
   计算真正胜出的声明。
2. **解析错位**：规则体内的 `/* */` 注释会被 `([^{}]*)\}` 吞掉导致花括号不闭合，
   **后续整段规则全部解析错位**——这正是"明明已复位却被报泄漏"的原因。
   新增 `stripComments()`，把注释替换为等长空白（保留行号）后再解析。

修完后候选 **100 → 79 条真实**，分三类处理：

```text
已被 V2 层接管（历史层未胜出）    89 条  → 无需处理
历史值即 V2 期望值                59 条  → 登记进 ALLOWED_LEGACY，逐条写明理由
需要真正改写                      少数   → 新增 §2.1 / §2.2 复位区块
```

真正改写的包括 `.breadcrumb-item` 的历史色 `--win-blue`（Google Drive 时代的蓝）
→ `--color-accent`；`.sort-select` 在窄屏的 `min-height:40px`（会把紧凑工具栏顶高）
→ 固定 32px；`.address-bar` 的 `border-radius`（`border: 0` 不会重置它）。

**新增 `--strict` 闸门**（已写入 `AGENTS.md` Step 7）：有未处理泄漏时返回非 0。
确认要保留的历史属性应登记进 `ALLOWED_LEGACY` 并附理由，而不是让闸门失败。

> 过程记录一次真实回归：隐藏移动端面包屑后，历史层的 `.address-bar { order: 3 }`
> 变成未处理泄漏。虽然 `display: none` 下 `order` 无影响，但**没有用白名单绕过**，
> 而是显式声明 `order: 0`——避免将来取消隐藏时位置突然不对。
