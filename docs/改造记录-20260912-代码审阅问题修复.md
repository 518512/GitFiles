# 改造记录 20260912 代码审阅问题修复

## 修改了什么

处理代码审阅报告中的全部高/中/低优先级问题，涉及 Worker 数据面、认证投递与文档。

### 高优先级

| 编号 | 问题 | 修复 |
|---|---|---|
| H1 | OAuth callback 把授权码 `postMessage` 到 `state` 里内嵌的任意 origin | 新增 `allowedDeliveryOrigins()` / `resolveDeliveryOrigin()`，只允许投递到本页 origin 与 `CONFIG` 中显式配置的 origin，其余一律回退到本页 origin |
| H2 | `/file` 下载把整个文件读进 Worker 内存，无大小上限、不支持 Range | 新增 `streamFile()`：透传 `response.body`、转发 `Range` 与 `206/416`、超过 95 MB 返回 413；不再走 `response.text()` |
| H3 | D1 ACL 缓存永不刷新，撤权后仍可见/可写 | `requireRepositoryAccess()` 增加 `checked_at` TTL；**写操作 TTL=0（每次强制回源 GitHub 校验）**；仓库列表支持 `?refresh=1` |
| H4 | `btoa(unescape(encodeURIComponent(...)))` 遇孤立代理项抛 `URIError` → 500 | 改用 `TextEncoder` 转字节，并显式拒绝未配对代理项返回 422（避免静默写成 U+FFFD） |
| H5 | 大文件下载二次缓冲 | 随 H2 一并解决 |

### 中优先级

- **M1** `delete` 不存在路径此前静默成功；现在返回 `skipped` + `missingPaths`，前端可提示「远端已无此路径」。
- **M2** 超大仓库递归 tree 被 GitHub 截断时，原实现直接 422 导致**完全无法写入**；改为按子树逐个惰性遍历（`readTreeIndex`），上限 2000 个目录。
- **M3** 批量 blob 串行上传改为**有界并发**（8 路），并把「文本/字节」去重键提取为 `contentKeyOf`。
- **M4** 新增 `purgeExpiredSessions()`，在 `/api/me` 上顺带清理过期 session 与 ACL；`workers/schema.sql` 改为幂等（DROP + CREATE）以便在已有部署上补列。
- **M5** 429 错误保留 `Retry-After` / `X-RateLimit-Reset` 到 `error.details`。
- **M6** 所有入库路径做 Unicode **NFC 规范化**，避免 macOS 的 NFD 文件名在 Git 中生成重复文件。同时为**历史仓库中已存在的 NFD 路径**增加兼容查找（`nfcPaths` / `nfcPrefixes`），保证旧文件仍可被 update / delete / rename，不会因规范化退化成「找不到路径」。

### 低优先级

- **L1** README 测试徽章与实际不符。
- **L3** 删除已无引用的 `githubRaw` 导出。
- `githubdisk.js` 的「连接仓库」改用 `/api/repos?refresh=1` 强制刷新。

## 为什么改

审阅发现的最严重问题是**认证码可被投递到攻击者域**，以及**下载大文件会打爆 Worker 内存**；其次是 ACL 陈旧导致**撤权后仍可写入**，这直接违反 AGENTS.md「权限安全」。M1/M2 属于 AGENTS.md §25「禁止假成功」与 §27「避免无意义失败」。

## 遗留问题

- **跨仓库 Move/Copy 的可恢复状态机**尚未实现（PROJECT_SPEC §9），失败时仍只报告错误，缺少 retry/cleanup UI。
- **文本三方合并**未实现，Conflict Center 目前仍只有「重新加载远端状态」。
- **GitHub App installation token** 尚未替代 OAuth user token，session 轮换也未实现。
- `streamFile` 的 95 MB 上限是 Worker 内存保护值，超过该大小的仓库文件仍无法下载（需要 R2 中转才能真正支持）。
- 本次未做真实 D1/Worker 端到端部署验证，`checked_at` 迁移的线上表现需在部署后确认。
