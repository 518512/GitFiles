# 改造记录 20260912 系统排查 CSS 并修正重复文案

## 修改了什么

用户反馈两点：**顶栏文案仍然显示**、要求**系统排查 CSS**。做了系统性排查，
并新增了一个可复用的排查工具。

### 1. 为什么上一轮的隐藏"没生效"——找到了真正的原因

上一轮我把 `#header-repo-state`（显示 `owner/repo · 分支`）设为 `display: none`。
复查确认**这个规则是生效的**：

```bash
grep -n "header-repo-state" public/css/ui-v2.css
# 130:.header-repo-state { display: none; }
```

构建产物正确、样式表顺序正确（`style.css` → `ui-v2.css`）、层级无 `!important` 干扰。

**真正重复的是另一处**：面包屑的首段。

```text
登录后首页:      GitFiles
进入仓库后:      GitFiles › my-repo › docs
进入本地存储后:  GitFiles › 本地存储
```

而**同一时刻顶栏左侧的品牌按钮**文本也是 `GitFiles`。
即 `ROOT_NAME`（取自 `SITE.name`）作为面包屑根条目，与品牌按钮完全重复——
这就是「顶栏还是显示 GitFiles-Repo名」的来源。

**修复**：面包屑在 storage / 仓库内部时**不再渲染根条目**。

```js
const crumbs = state.level !== 'home' && state.breadcrumbs[0]?.id === ROOT_ID
  ? state.breadcrumbs.slice(1)
  : state.breadcrumbs;
```

安全性：根条目的作用是「返回工作区首页」（`navigateToCrumb` 的 `ROOT_ID` 分支），
而**品牌按钮本身就是同一个入口**（`title="返回工作区首页"`），所以能力没有丢失。
首页态下只剩根条目，则保持原样渲染。

### 2. 系统排查 CSS：新增 `scripts/audit-css.mjs`

问题背景：本项目有两层样式表——`style.css`（上游时代历史层，约 3400 行）
与 `ui-v2.css`（V2 覆盖层）。历史规则是在**旧布局**下写的；当元素被搬进新结构后，
旧的定位/装饰属性依然生效，产生「多余横线」「割裂色块」这类问题。
靠肉眼逐页看很难查全。

新增的审计脚本对给定类名：

- 列出它在两层样式表里的**全部规则**（含来源文件、行号、是否在 `@media` 内、是否 `!important`）；
- 标出**「历史层设置了、V2 层未显式复位」的属性**——这些就是泄漏候选；
- 默认审计 UI 已知的迁移元素清单，也可指定类名。

```bash
node scripts/audit-css.mjs                 # 审计默认清单
node scripts/audit-css.mjs ribbon file-tools  # 指定类名
```

**首次运行发现 100 条候选**，本次处理了 ribbon 相关的部分。

### 3. 按审计结果修复的问题

| 元素 | 历史属性 | 处理 |
|---|---|---|
| `.file-tools` | `background: #fff` + `border-bottom: 1px` | V2 已复位（上一轮），本次确认 |
| `.search-box` | 边框、圆角、白底 | 在 ribbon 内改为扁平风格，仅 hover/focus 给反馈 |
| `.sort-select` | 边框、圆角、白底 | 同上，透明背景避免与工具栏"分块" |
| `.address-bar` | `border: 1px`、`border-radius: 6px` | 复位。**注意 `border: 0` 不会重置 `border-radius`**，需单独写 |
| `.breadcrumbs` | `flex: 1`、`overflow: hidden` | 保留 `overflow: hidden`（横向滚动需要） |
| `.view-toggle` / `.nav-buttons` | `display: flex`、`gap: 2px` | 集中复位 |

新增 **§2.1 历史元素迁移复位** 区块，把这一批复位集中写在一处并注释原因——
即便某处特异性侥幸生效，也把意图写清楚，避免以后调布局时又被历史属性咬到。

### 4. 修正文档中不准确的 fork 表述

用户指出 fork 并未移除。实际查询 API 确认：

```json
{ "fork": true, "parent": { "full_name": "fi3ik-mme/storage-hub" } }
```

此前 `AGENTS.md`、`README.md`、`README_EN.md`、`docs/架构现状-20260912.md`
都写了「已脱离 fork 网络」——**这是错误陈述**。全部更正为「按独立项目维护，
GitHub 平台层面的 fork 标记尚未解除」，并记录了解除方法与前置条件。

## 为什么改

- 「文案没生效」的真实原因不是 CSS 没生效，而是**我看错了元素**：
  重复来自面包屑根条目，不是 `header-repo-state`。上一轮我的判断不够严谨。
- 两层样式表的冲突会**持续复发**（每次搬动布局都可能引入），
  必须工具化排查，而不是遇到一个修一个。
- 文档写了未发生的事，比没写更糟——尤其"已脱离 fork"这种可被一行 API 验证的事实。
