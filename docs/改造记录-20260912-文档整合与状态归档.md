## 为什么改

整合前的问题：

1. **状态信息散落在三处**：`PROJECT_SPEC.md` §12、两份审查报告、以及各改造记录，
   互相矛盾且都在说「待完成」，但实际多数已完成。
2. **两份审查报告已严重过时**：写于上游时代，其 P0 问题（token 存 localStorage、
   无 Worker）此后已被整体重写解决，但文档仍以「待办」语气呈现，
   后来者据此开发会走错方向。
3. **两份重要文档放在仓库根目录**且未被 git 跟踪。
4. **改造记录数量多且无索引**，且没有说明其中一批 UI 提交的效果被层叠问题压制。
5. **缺少 fork 关系的正式说明**：`AGENTS.md` 只说禁止向上游提 PR，
   但没有回答「这还算 fork 吗」这个反复出现的疑问。
