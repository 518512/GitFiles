# GitHub 登录与 D1 部署缺陷修复

## 修改了什么

- 为 Worker 发往 GitHub REST API 的普通请求和 raw 文件请求补充 `User-Agent: GitFiles-Worker`。
- 修复 GitHub 因缺少 User-Agent 返回 `Request forbidden by administrative rules`，导致 OAuth session 初始化失败的问题。
- 修复 Workers 根路径默认配置，避免 `/GitFiles` 路径污染 Worker 的 OAuth callback 和 `/api` 请求。
- 修复 `GithubDisk` 冲突监听导出缺失导致 `App.init()` 中断的问题。
- 为旧缓存版本增加兼容调用，并通过 Service Worker 版本切换避免 app.js/githubdisk.js 混用。
- 将 `config.runtime.js` 加入 PWA shell 资源。
- 明确 D1 database ID 不提交到公共仓库；每个部署者在 Cloudflare Worker Settings → Bindings 中绑定自己的 D1，变量名固定为 `DB`。
- 增加 GitHub User-Agent 回归测试。

## 为什么改

GitHub API 对 User-Agent 有要求，缺失时即使 OAuth client ID、secret 和 D1 均正确，登录后的用户查询仍会失败。此前错误在前端表现为登录按钮无响应或 session 初始化失败。

D1 database ID 属于部署者账号资源，不能写死到公共仓库。Worker 代码只依赖 `env.DB`，因此公共配置应固定 binding 名称而不是固定数据库 ID。

## Cloudflare 后台要求

每个部署者需要在自己的 Worker 中配置：

```text
D1 binding variable name: DB
Runtime secret: GITHUB_CLIENT_SECRET
Build variable: CONFIG_GITHUB_CLIENT_ID
```

D1 database ID 不写入公共仓库。修改 binding 或变量后需要重新部署，并清理旧 Service Worker 缓存。
