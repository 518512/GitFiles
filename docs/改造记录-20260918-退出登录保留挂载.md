# 改造记录：退出登录不再卸载存储（挂载按账号自动恢复）

> 日期：2026-09-18 · 范围：`js/app.js`、`js/githubdisk.js`、`js/contextmenu.js`、
> `js/notepad.js`、`index.html`、`tests/app-session.test.mjs`

## 1. 问题

用户报告：**退出登录后重新登录，之前挂载的库不见了**。

排查后发现比"丢挂载"更严重：

```text
signOutGithub()
  └─ ejectAllDrives()
       ├─ GithubDisk.removeDisk(diskId)      → 删除 GitHub 挂载记录
       └─ LocalDisk.removeDisk(diskId)
            └─ deleteAllForDisk(diskId)      → 连本地存储的 IndexedDB 数据一起删除
```

也就是说，**「退出登录」等于「清空本地数据 + 卸载全部存储」**。GitHub 仓库内容在
远端不受影响，但本地存储卷里的文件是永久丢失的。这正是审阅报告里 B-4 记的那条，
当时我判断"属行为变更、需产品确认"而搁置——现在需求明确了。

## 2. 修改了什么

### 2.1 退出登录只结束会话

```js
async function signOutGithub() {
  await GithubApi.request('/api/logout', ...);   // 撤销 Worker 会话 + 清 Cookie
  githubLogin = null; githubAvatar = null;
  state.githubSession = 'expired';
  GithubDisk.setActiveAccount(null);             // 清账号归属
  resetSessionScopedState();                     // 只清内存缓存
  Router.syncUrl([], false);                     // 重置深链地址
  renderGithubSessionState();
  showLogin();
}
```

`resetSessionScopedState()` 只重置内存里与会话绑定的状态（当前目录、选中、搜索、
侧栏树缓存、配额缓存、按仓库的树缓存），**完全不触碰 localStorage 的挂载记录，
也不触碰本地存储的 IndexedDB 数据**。

### 2.2 挂载按账号保留 + 按账号过滤

`js/githubdisk.js` 新增：

```text
setActiveAccount(login)   记录当前 Worker 会话的登录名（app.js 在 /api/me 成功后调用）
getVisibleDisks()         只返回属于当前账号的挂载
getDisks()                仍是不过滤的全量列表（供卸载/持久化使用）
```

`getVisibleDisks()` 的规则：

- 账号**未知**时不过滤（例如 `/api/me` 暂时不可用）：不能因为连不上就把用户的存储
  藏起来；真正的访问控制始终由 Worker 侧 ACL 兜底。
- 账号已知时，只显示 `accountLogin` 匹配当前登录名的挂载（大小写不敏感）。
- 没有 `accountLogin` 的早期记录无法归属，按可见处理。

界面枚举点全部改用 `getVisibleDisks()`：首页文件项、侧栏树、概览计数、
配额刷新、账户菜单、根上下文菜单与属性面板。`ejectAllDrives()` 仍用 `getDisks()`
——它是"移除所有存储"这个显式破坏性操作。

### 2.3 重新登录后自动恢复

`signInWithGithub()` 成功后不再手写 `state.githubSession = 'connected'`，而是调用
`refreshGithubSessionState()`：

```text
/api/me → githubLogin = me.login → GithubDisk.setActiveAccount(login)
        → showExplorer() → 首页/侧栏按账号列出挂载
```

这同时修掉了一个附带问题：此前**新登录（未刷新页面）时 `githubLogin` 一直是 null**，
账户菜单只能靠"第一个挂载的 accountLogin"兜底显示。

### 2.4 文案：把"退出登录"和"删除数据"区分开

原来的确认框是英文且没有数据删除警告，容易让人以为"卸载 = 退出登录"。现在：

```text
移除本地存储   → 明确写"其中保存的所有文件都会被永久删除，无法恢复"，
                 并提示"若只是想退出登录，请用账户菜单里的「退出登录」"
卸载 GitHub 存储 → 说明"只移除本应用里的挂载记录，GitHub 上的仓库内容不受影响"
移除所有存储   → 明确写"本地存储中的文件数据会被永久删除"
账户菜单退出项  → 加 title「仅结束 GitHub 会话：已挂载的存储会保留，重新登录后自动恢复」
```

## 3. 为什么这样改

- **第一原则是数据正确性**：登录态是"会话"，挂载是"数据"。退出登录不应该删除数据，
  这是语义错误而不只是体验问题。
- **按账号过滤是必要的配套**：如果只是"不删除"，换账号登录就会看到（并尝试访问）
  上一个账号的仓库。保留记录 + 按账号展示，既满足"同账号自动恢复"，又不会串号。
- **未知账号不过滤**是刻意的保守选择：宁可多显示（访问仍会被 Worker ACL 拒绝），
  也不要因为在弱网/上游故障时把用户的存储"藏"起来。


新增的 `tests/app-session.test.mjs` 用两种手段锁住这个 bug：

1. **数据层**（真实加载 `js/githubdisk.js`）：
   - 未设置账号时 `getVisibleDisks()` 返回全部（回退行为）；
   - 设置账号后只返回该账号（大小写不敏感）+ 无归属记录；
   - 反复切换账号后 `getDisks()` 数量不变——换账号只是"看不见"，记录必须还在。
2. **源码层**（静态断言 `js/app.js`）：
   - `signOutGithub()` 体内不得出现 `ejectAllDrives` / `ejectGithubDisk` /
     `ejectLocalDisk` / `removeDisk` / `deleteAllForDisk`；
   - 必须调用 `setActiveAccount(null)` 与 `resetSessionScopedState()`，且仍打 `/api/logout`；
   - `resetSessionScopedState()` 不得出现 `removeDisk` / `deleteAllForDisk` /
     `localStorage.removeItem`。

源码层断言看起来笨，但它精确对应这次回归：旧代码就是在一行里调用 `ejectAllDrives()`。

## 6. 遗留问题

- **未做真机验证**：需要在真机上走一遍「挂载 → 退出 → 重新登录（同一账号）」
  与「退出 → 换账号登录」两条路径。前者应看到挂载自动回来，后者不应看到他人挂载。
- 记事本独立页（`notepad.html`）没有 `activeAccountLogin`（它不复用 app.js 的会话
  状态），因此其"另存到其他位置"仍会列出全部挂载。属于既有行为，未在本轮扩大改动。
- 「移除本地存储 / 移除所有存储」仍会删除本地数据（这是它们的语义），只是文案现在
  说清楚了。如果希望"卸载挂载但保留数据"，需要为本地卷引入可重新挂载的概念。
- 挂载记录目前不做过期校验：如果某仓库在 GitHub 上被删除或撤权，它仍会显示，
  访问时由 Worker 返回 403/404 并提示重新授权。可在后续加"挂载健康检查"。
