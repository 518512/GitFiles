# 改造记录：修复预览存储匹配

## 修改了什么

- 独立记事本页面优先读取主页面写入的文件 handoff。
- 使用 handoff 中的 `userId` 和文件元数据直接打开本地/GitHub 文件。
- 保留手动访问 URL 或 handoff 过期后的存储名称路径解析作为兜底。

## 为什么改

主界面打开文件时已经通过 localStorage 保存了精确的存储 ID 和文件信息，但独立页面此前先根据 URL 第一个路径段查找存储名称。存储名称包含空格、编码字符、旧名称或发生改名时，会在读取 handoff 前失败并显示“找不到存储空间”。

## 涉及文件

`js/notepad.js`。

## 测试情况

- JavaScript 语法检查通过。
- Git 引擎测试和 Worker/API 测试通过。
- 构建产物检查通过。

## 遗留问题

直接复制且 handoff 已过期的旧 URL 仍需要依赖存储名称解析；该路径保持原有行为。
