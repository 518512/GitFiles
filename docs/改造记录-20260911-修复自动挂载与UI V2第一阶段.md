# 改造记录：修复自动挂载与 UI V2 第一阶段

## 修改了什么

- 移除登录成功后自动同步并挂载全部 GitHub 仓库的逻辑，恢复“登录只认证、用户主动添加仓库”的产品边界。
- 退出 GitHub 按钮默认隐藏，仅在会话状态为 `connected` 时显示。
- 将缓存清理、移除全部存储等界面文案中文化。
- 新增 UI V2 表现层 `css/ui-v2.css`，建立颜色、间距、边框、圆角、Header、Sidebar、Workspace、列表和移动端基础设计系统。
- 新增 App Header：品牌返回、全局搜索、添加入口、仓库状态和账户状态入口。
- 新增 Repository Header，显示 `owner/repo`、仓库可见性、分支和文件/历史结构。
- 增加移动端单列列表和 Drawer 兼容样式。
- 将新样式和资源加入 Worker 构建及 Service Worker 缓存。

## 为什么改

7bda17d 将登录后的仓库发现结果全部写入本地挂载列表，导致登录用户默认挂载账号下所有 Repository，违反 UI V2 任务单中“Connected 与 Available 必须区分”的要求。UI V2 需要以 Repository Workspace 为核心，同时不改变现有 Git Data、认证、权限和文件操作业务实现。

## 涉及文件

`js/app.js`、`js/githubdisk.js`、`js/contextmenu.js`、`index.html`、`404.html`、`css/ui-v2.css`、`sw.js`、`js/app-version.js`、`GitFiles UI V2 重构任务单.md`。

## 删除的旧代码

- 删除 `js/githubdisk.js` 中登录后自动同步全部仓库的 `syncAvailableRepositories` 实现及导出。
- 未删除现有文件操作、Conflict Center、OAuth、Session、Git Data API 逻辑。

## 新 UI 架构

- Header：品牌、搜索、添加、仓库状态、账户状态。
- Sidebar：工作区导航、存储导航、已挂载存储树。
- Workspace：Repository Header、路径导航、文件视图、状态栏。
- Repository：突出显示 `owner/repo`、可见性和分支。
- FileList：保留现有 Grid/List、搜索、排序和多选操作。
- Dialogs/Menus：继续复用现有统一 Dialog 和 Context Menu。
- Mobile：顶部紧凑 Header、Drawer、单列文件列表和底部选择栏。

## 测试情况

- JavaScript 语法检查通过。
- Git 引擎测试和 Worker/API 测试通过。
- 构建产物检查通过。
- `git diff --check` 通过。

## 性能影响

- 未增加 API 请求。
- 删除了登录后的自动仓库发现请求。
- 新增少量 Header/Repository DOM，不改变文件列表数据流。
- 新增一个 CSS 文件，未引入第三方依赖。

## 遗留问题

- Repository Picker 仍复用现有 Dialog，尚未重构为独立搜索列表。
- Branch Selector 和 History 页面尚未实现完整交互。
- Markdown 仍是文本编辑器预览，不是渲染后的 Markdown 预览。
- 旧 `style.css` 仍包含历史规则，后续需要在视觉回归后分批清理。
