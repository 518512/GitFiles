# 改造记录：修复一键部署报错与构建命令为空

- 日期：2026-09-08
- 关联：`docs/改造记录-20260908-配置体系模板化.md`

## 用户报告的问题

1. 一键部署（Deploy to Cloudflare 按钮）报错：`WorkerResource.getWorkerResult: response missing default_environment.script`
2. Dashboard 中 Pages 项目的构建命令（Build command）为空

## 原因分析

- `wrangler.jsonc` 中混用了 **Pages** 字段（`pages_build_output_dir`）与 **Workers static assets** 字段（`assets.not_found_handling`），一键按钮流程按 Worker 资源解析时产生歧义，触发上述报错；而 Pages 的 404 回退本来就靠根目录 `404.html` 约定，`assets` 块纯属多余
- **Pages 的 Git 集成不读取 `wrangler.jsonc` 的 `build` 字段** —— 构建命令只在 Dashboard 项目设置中生效，因此用户看到构建命令为空（按钮流程创建的项目不带命令）
- 结论：按钮流程对"纯静态 Pages"项目不可靠，不应作为主推路径

## 修改了什么

### 1. `wrangler.jsonc` 精简

- 删除 `assets` 块（消除 Worker/Pages 歧义，404 回退由 `404.html` 约定承担）
- 保留 `build.command: node scripts/build-config.mjs`（`wrangler pages deploy` CLI 部署时自动执行）
- 注释明确两条部署路径对构建命令的支持差异（CLI 自动 / Git 集成需在 Dashboard 填写）

### 2. 双语 README 部署章节重排

- **方式一（推荐）：Dashboard Git 连接** —— 完整步骤：Connect to Git → Framework preset `None` → Build command 填 `node scripts/build-config.mjs`（留空也能部署，仅环境变量注入渠道失效）→ Variables and Secrets 配置 `CONFIG_*` 与 `GITHUB_CLIENT_SECRET`
- **方式二：wrangler CLI 直接部署**（`npx wrangler pages deploy .`）
- **方式三：Deploy 按钮（降级为备选）** —— 明确标注已知报错与补救办法
- **方式四：GitHub Pages**（原方式二，编号顺延）
- 英文版补充说明同步，并修复上轮替换时误删的两节（GitHub Pages 小节、token 代理对照表），两文件章节结构已对齐
